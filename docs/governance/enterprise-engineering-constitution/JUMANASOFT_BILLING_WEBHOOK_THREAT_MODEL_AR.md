# نموذج مصفوفة التهديدات الأمنية لإشعارات الدفع (Jumanasoft Billing Webhook Threat Model)

* **المشروع:** منصة نما الطبية (NamaMedical ERP)
* **المرحلة:** إعداد بوابات الدفع التجريبية مستندياً (PHASE_BILLING_SANDBOX_PREP_DOCS_ONLY)
* **البوابة:** البوابة 3.1 — تهديدات الـ Webhooks (Gate 3.1 — Webhook Threat Model)
* **الحالة:** تم التوثيق والفرض بنجاح (ENFORCED) ✅

---

## 1. مصفوفة التهديدات الأمنية وتحليلها (Threat Matrix)

تم تحليل المخاطر المحتملة التي قد تستهدف قنوات استقبال إشعارات الدفع (Webhooks) وتحديد طرق الوقاية منها:

| التهديد الأمني (Threat) | تفاصيل وخطر التهديد | آلية الدفاع والوقاية المصممة مستقبلاً |
| :--- | :--- | :--- |
| **الأحداث المزيفة (Spoofed Events)** | محاولة مهاجم إرسال حزم دفع وهمية لترقية باقات عياداته دون دفع حقيقي. | فرض التحقق الرقمي للتوقيع الرقمي (Signature Verification) باستخدام سر موحد ومخفي. |
| **هجوم التكرار (Replay Attacks)** | محاولة المهاجم التقاط حدث ناجح وإعادة إرساله لتكرار إمداد الباقات بالترقية. | تفعيل صمام المهلة الزمنية (Timestamp tolerance) ورفض الأحداث القديمة. |
| **معالجة مكررة (Duplicate Delivery)**| قيام بوابة الدفع بإرسال نفس الحدث مرتين بسبب مشاكل شبكة مؤقتة. | فرض قيد فريد (Unique Constraint) على معرف الحدث `provider_event_id_hash`. |
| **الترتيب المتداخل (Out-of-order)** | استلام حدث إلغاء قبل حدث نجاح الدفع بسبب تداخل أوقات النقل. | فحص الحالات الزمنية للمعاملة وتحديث الحساب بناءً على التاريخ الفعلي للمعالجة. |
| **تلاعب بالبيانات (Payload Tampering)**| تعديل قيمة المبلغ أو نوع العملة أثناء نقل الحدث. | التحقق من التوقيع الرقمي ومطابقة المبلغ بالـ `Checkout Session` المخزنة داخلياً. |
| **تعطيل الخدمة (Large Payload DoS)** | إرسال حزم ضخمة جداً لتعطيل الخادم وشل حركة استقبال الفواتير. | تقييد حجم البيانات المستلمة (Payload Size Limits) على الخادم (مثال: حد أقصى 10KB). |
| **تداخل هويات المستأجرين** | محاولة إدخال حدث مستأجر لحساب مستأجر آخر (Cross-tenant leak). | فرض مطابقة معرف المستأجر `tenant_id` المشفر والمقترن بالـ RLS عند المعالجة. |
| **تسريب الأسرار في السجلات** | طباعة محتويات الـ Webhook كاملة في سجلات الكونسول مما يكشف الأسرار. | فلترة وتطهير الحزم (JSONB sanitization) وحظر طباعة أي معرفات أو مفاتيح حية. |

---
**القرار:** تم صياغة وتوثيق مصفوفة التهديدات الأمنية للـ Webhooks، ومصرح بالانتقال لـ GATE 3.2 لتصميم آليات التحقق الرقمي.
