* **المشروع:** منصة نما الطبية (NamaMedical ERP)
* **المرحلة:** تصميم أساس محول الفواتير (PHASE_BILLING_ADAPTER_DESIGN_ONLY_CANDIDATE)
* **البوابة:** البوابة 3.1 — قرار نطاق الكود (Gate 3.1 — Decide Code Scope)
* **القرار المعتمد للمرحلة:** السماح بكتابة كود المحول النظيف التجريبي (`CODE_CANDIDATE_ALLOWED`) ✅

## 1. تفاصيل خيارات نطاق الكود وتقييمها

تم دراسة وتقييم خيارات كتابة كود برمجيات الفوترة في هذه المرحلة لضمان السلامة المطلقة:

1. **الخيار الأول (DOCS_ONLY_REQUIRED):**
   * قصر العمل على التقارير المستندية فقط دون كتابة أي أسطر برمجية.
   * *التقييم:* آمن جداً، لكنه يحرم المطورين من وجود مرجع برمجي نظيف للتطوير اللاحق.
2. **الخيار الثاني (CODE_CANDIDATE_ALLOWED):**
   * بناء ملف برمجيات محول فوترة نقي (Pure JS Module) يقتصر بالكامل على معالجة المنطق الرياضي والتحقق من صحة المعاملات، ويعتمد حصرياً على موفر وهمي (MockProvider) دون أي اتصال بقاعدة البيانات أو استدعاءات شبكة خارجية.
   * *التقييم:* **معتمد**؛ كونه آمن بنسبة 100% ولا يلمس أي بيئة حية أو قاعدة بيانات، ويوفر أساساً برمجياً ثابتاً للمشروع.

---

## 2. شروط وقيود كتابة الكود البرمجي للمحول

* **حظر الاتصال بالشبكة (No HTTP Calls):** يُمنع استخدام `fetch` أو `axios` للاتصال ببوابات Moyasar أو Stripe أو غيرها.
* **حظر الاتصال بقاعدة البيانات (No DB Reads/Writes):** يعمل الكود كمنطق نقي (Functional logic) دون استعلام الجداول.
* **الافتراض الافتراضي للموفر (Default Mode):** موفر الدفع التجريبي `mock` هو المفعل الوحيد ولا يمكن تهيئة البوابات الأخرى.
