# حزمة إجراءات المالك لتهيئة بيئة الاستضافة التجريبية (Jumanasoft Owner/DevOps Staging Action Packet)

* **المشروع:** منصة نما الطبية (NamaMedical ERP)
* **المرحلة:** تهيئة وفحص بيئة Staging وتجهيز الجداول (PHASE_ENTERPRISE_FACILITY_PLATFORM_STAGING_PROVISIONING_AND_DDL_PREP)
* **المستند:** حزمة إجراءات المالك والـ DevOps (PHASE_ENTERPRISE_FACILITY_PLATFORM_STAGING_OWNER_ACTION_PACKET_AR)
* **الحالة:** تم تأسيس البيئة وإرجاع الأدلة (OWNER_DEVOPS_STAGING_PROVISIONED_READY) ✅

---

## 1. توجيهات أمنية هامة للـ DevOps والمالك
> [!WARNING]
> * **يمنع منعاً باتاً إرسال كلمات المرور أو روابط الاتصال الكاملة أو محتويات ملفات البيئة الحساسة في تقارير المراجعة أو سجلات الجلسة.**
> * يرجى الاكتفاء بنموذج الإقرار الثنائي (YES/NO) وحالات الموارد فقط لتأكيد الجاهزية.

---

## 2. قائمة الإجراءات والخطوات المطلوبة للتأسيس (Resource Plan)
يُطلب من مهندس العمليات (DevOps) أو مالك النظام اتخاذ الخطوات التالية لتأسيس بيئة Staging معزولة وآمنة:

1. **خادم الاستضافة (Staging Host):** إنشاء خادم سحابي مستقل (VM) مخصص لبيئة الاختبار لتفادي مشاركة الموارد مع الإنتاج.
2. **قاعدة البيانات (Staging DB):**
   * إنشاء قاعدة بيانات جديدة مخصصة بالاسم: `nama_medical_staging`.
   * إنشاء مستخدم مقيد بالاسم: `nama_staging_user`.
   * **محدد الأمان:** يجب ألا يملك المستخدم صلاحية `SUPERUSER` أو `BYPASSRLS`. ويمنع منعه التام من الوصول لقاعدة بيانات الإنتاج الفعلي.
3. **عملية التشغيل (PM2 Process):** تشغيل التطبيق كعملية PM2 مستقلة بالاسم: `nama-app-staging`.
4. **منفذ الاتصال (Port):** ضبط التطبيق ليعمل على المنفذ المخصص للاستضافة التجريبية `3010`.
5. **ملف التهيئة (Env File):** إنشاء وتأمين ملف التهيئة المخصص `.env.staging` على الخادم وحمايته من التتبع في مستودع Git.
