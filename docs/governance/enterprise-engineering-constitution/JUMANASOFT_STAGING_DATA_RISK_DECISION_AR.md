# تقرير قرار مخاطر البيانات في بيئة الاختبار (Jumanasoft Staging Data Risk Decision Report)

* **المشروع:** منصة نما الطبية (NamaMedical ERP)
* **المرحلة:** مراجعة أمان بيئة الاختبار وقرار البنية التحتية (PHASE_STAGING_SECURITY_REVIEW_AND_REAL_INFRA_DECISION)
* **البوابة:** البوابة 3 — قرار مخاطر البيانات (Gate 3 — Data Risk Decision)
* **القرار المعتمد:** الخيار أ — متطلبات بيئة اختبار حقيقية معزولة (`REAL_STAGING_REQUIRED`) ⚠️

---

## 1. تحليل مخاطر البيانات الحالية

بناءً على تصنيف البيانات الحالي كبيانات مشتقة من الإنتاج وغير مطهرة (`PRODUCTION_DERIVED_UNSANITIZED`) داخل قاعدة الاختبار المحلية `jumanasoft_staging` المأخوذة عبر `pg_dump` من قاعدة البيانات الحية، تم دراسة وتقييم المخاطر التالية:

* **الوضع القائم:** تحتوي البيئة المحلية الحالية على بيانات مرضى حقيقية (PHI/PII)، ولا يوجد أي دليل أو سكربت تطهير معتمد لتأمينها.
* **الخيار المعتمد للمشروع:** **الخيار أ (`REAL_STAGING_REQUIRED`)**
  * *التبرير:* يتطلب المشروع تفعيل ومحاكاة ميزات SaaS والخطط والإنفاذ (`observe/enforce`) وتجاوز اختبارات Smoke الحقيقية بشكل رسمي وتكامل آمن قبل النشر للإنتاج. هذا يتطلب بيئة staging مستقلة تماماً ومحمية ومعزولة بنيوياً على مستوى الشبكة والخوادم وDNS مخصص.
* **حظر إدعاء الأمان:** يُمنع منعاً باتاً اعتبار بيئة التطوير الحالية آمنة للاستخدام العام أو مشاركة اعتماداتها أو فتح DNS عام لها ما لم يتم تطبيق شروط العزل الكاملة الواردة في البوابة 4.

---

## 2. مصفوفة القرارات وخطة العمل

| خيارات العلاج والتعامل | القرار والتقييم | الشروط المطلوبة للتنفيذ |
| :--- | :---: | :--- |
| **الخيار أ: توفير بنية تحتية حقيقية معزولة (`REAL_STAGING_REQUIRED`)** | **معتمد (SELECTED)** | توفير خادم مستقل، DNS مستقل (`staging.jumanasoft.com`)، قاعدة بيانات مستقلة بعيدة عن الإنتاج، وحارس فشل آمن. |
| **الخيار ب: تعقيم قاعدة البيانات المحلية (`LOCAL_SANITIZATION_REQUIRED`)** | **موصى به كبديل مؤقت** | كتابة وتشغيل سكربت تطهير معتمد (Sanitizer) يستبدل كافة السجلات والبيانات الشخصية الحساسة ببيانات وهمية وإثبات حالة التطهير (`SANITIZED_PROVEN`). |
| **الخيار ج: حجب التشغيل بالكامل لعدم الأمان (`BLOCKED_NO_SAFE_RUNTIME_PATH`)** | **مستبعد حالياً** | يُلجأ إليه في حال تعذر توفير البنية التحتية المعزولة أو تعقيم البيانات البرمجية المحلية. |

---
**القرار النهائي:** اعتماد متطلبات توفير بنية تحتية حقيقية معزولة (`REAL_STAGING_REQUIRED`) كشرط أساسي لفك حجب ميزات الإنفاذ وتفعيل البيئة الاختبارية بشكل رسمي.
