# متطلبات تعقيم وتطهير قاعدة البيانات المحلية (Jumanasoft Local Staging Sanitization Requirements)

* **المشروع:** منصة نما الطبية (NamaMedical ERP)
* **المرحلة:** مراجعة أمان بيئة الاختبار وقرار البنية التحتية (PHASE_STAGING_SECURITY_REVIEW_AND_REAL_INFRA_DECISION)
* **البوابة:** البوابة 5 — متطلبات تعقيم البيانات المحلية (Gate 5 — Local Sanitization Requirements)
* **الحالة:** معتمد وتحديد المواصفات (APPROVED) ✅

---

## 1. تحديد الجداول والحقول الحساسة (PHI/PII)

عند الحاجة لتشغيل بيئة الاختبار المحلية (`jumanasoft_staging`) وإمدادها ببيانات من الإنتاج للاستخدام الداخلي المحدود، يجب إخضاع البيانات الحية لعملية تعقيم كاملة تشمل تطهير الجداول والحقول الحساسة التالية لمنع تسرب أي بيانات شخصية أو صحية:

1. **جدول المرضى (`patients`):**
   * استبدال الأسماء (`name_ar` / `name_en`) بأسماء وهمية اصطناعية.
   * استبدال أرقام الهوية أو الإقامات (`national_id`) بقيم عشوائية.
   * استبدال أرقام الهواتف (`phone`) بأرقام وهمية.
2. **جدول السجلات الطبية والتشخيصات (`medical_records` / `prescriptions`):**
   * إزالة وتعمية الملاحظات السريرية (`notes`) والتشخيصات التفصيلية وتجنب طباعتها في السجلات العامة أو سجلات الكونسول لمنع تسريب بيانات PHI.
3. **جدول الموظفين (`employees`):**
   * استبدال الأسماء الحقيقية والرواتب والبيانات الحساسة.
4. **جداول الفواتير والمعاملات المالية (`invoices` / `insurance_claims`):**
   * تعقيم السجلات وإزالة تفاصيل أرقام البطاقات التأمينية أو أرقام المطالبات الحقيقية والبيانات المالية الحساسة.

---

## 2. معايير تشغيل وحوكمة سكربت التعقيم (Sanitizer Governance)

* **التصميم كخطة مستقبلية:** يتم كتابة سكربت تطهير كخطوة علاجية مستقلة وقادمة ولا يُنفذ أو يُطرح في هذه الجولة البرمجية.
* **إثبات التطهير (`SANITIZED_PROVEN`):** لا يُسمح بإلغاء قيود أمان البيانات أو ادعاء جاهزية الفحص إلا بعد تقديم شواهد آلية واختبارات فحص تثبت خلو قاعدة البيانات من أي تطابقات مع السجلات الطبية الحقيقية للإنتاج.
* **قيود الاستخدام العام:** 
  * يمنع استخدام نطاق DNS عام أو إتاحة الوصول الخارجي للبيئة المحلية.
  * يمنع تفعيل ميزات `observe` أو `enforce` بشكل عام على هذه البيانات.
  * يقتصر عمل البيئة على التحقق البرمجي وفحص التوافق البنيوي محلياً داخل جهاز التطوير المعزول فقط.

---
**القرار:** تعتبر خطة تعقيم البيانات وإثباتها تشغيلياً (`SANITIZED_PROVEN`) متطلباً مستقبلياً إلزامياً في حال تقرر الاكتفاء بالبيئة المحلية للاختبارات دون بنية سحابية مستقلة.
