## 1. تعريف الوثيقة

هذه الوثيقة تجعل STITCH مسار التصميم الرسمي للواجهات قبل تحويلها إلى كود. الهدف ليس توليد شكل جميل فقط، بل إنتاج تصميم قابل للتحقق لكل قسم، شاشة، زر، حالة، صلاحية، وبيانات.

## 2. سياسة STITCH الإلزامية

1. يجب أن يبدأ كل قسم من Prompt STITCH واضح يحتوي: الهدف، المستخدمين، الأقسام، الشاشات، الأزرار، الحالات، الصلاحيات، اللغة، ونقاط السلامة.
2. يجب أن يكون كل تصميم ثنائي اللغة عند الحاجة، وRTL-first للعربية.
3. يجب أن يغطي كل تصميم حالات: empty, loading, error, permission denied, success, locked, audit required.
4. يجب ألا يحتوي تصميم STITCH على PHI حقيقية أو أسرار أو بيانات مرضى.
5. يجب تحويل كل تصميم إلى Acceptance Criteria قبل التنفيذ.
6. يجب ألا يعتمد أي زر خطر دون confirmation/reason/audit.
7. يجب أن تكون الأزرار واضحة: فعل، أثر، صلاحية، نتيجة، ورسالة خطأ.
8. يجب أن تُربط كل شاشة بمتطلبات القسم في Source Requirements.
9. يجب أن تُنتج مخرجات STITCH: Wireframe, user flow, components, design tokens, responsive behavior, Arabic copy.
10. يجب ألا ينتقل التصميم إلى الكود قبل مراجعة clinical safety وsecurity وtenant isolation.

## 3. STITCH Deliverables

| المخرج | الوصف | بوابة القبول |
| --- | --- | --- |
| STITCH_PROMPT | برومنت مفصل لكل مجال أو قسم | يغطي المستخدمين والشاشات والأزرار والحالات |
| WIREFRAMES | نماذج واجهة أولية | RTL، responsive، بلا PHI |
| MOCKUPS | تصميم بصري قابل للمراجعة | متوافق مع design system |
| USER_FLOWS | رحلات المستخدم | لا توجد خطوة بلا صلاحية أو audit |
| BUTTON_CATALOG | كل زر ووظيفته وشروطه | لا يوجد زر خطر دون حارس |
| COMPONENT_MAP | خرائط المكونات | قابلة للتحويل إلى UI |
| I18N_KEYS | مفاتيح ترجمة | عربي/إنجليزي منظم |
| ACCESSIBILITY_CHECK | إتاحة وقراءة | WCAG-oriented دون ادعاء شهادة |
| HANDOFF_REPORT | تقرير تسليم للمطور | يربط التصميم بالمتطلبات والاختبارات |

## 5. بوابات Auto Pilot الخاصة بالتصميم

| البوابة | المطلوب | قرار الإيقاف |
| --- | --- | --- |
| G0 | قراءة مصدر المتطلبات والفهرس | توقف إذا المصدر ناقص |
| G1 | تحديد القسم والشاشات والمستخدمين | توقف إذا الدور أو الرحلة غامضة |
| G2 | إنتاج STITCH prompt | توقف إذا لا يغطي الأزرار والحالات |
| G3 | مراجعة السلامة والخصوصية | توقف عند PHI أو زر خطر غير محكوم |
| G4 | تحويل التصميم إلى Acceptance Criteria | توقف إذا لا توجد معايير قبول |
| G5 | تسليم handoff | توقف إذا لا يوجد ربط بالاختبارات |

## 6. قاعدة مهمة

STITCH ليس بديلاً عن المعمارية أو الأمن أو CBAHI/PDPL/NCA. هو طبقة تصميم يجب أن تُثبت أنها لا تكسر الحوكمة.
