## 1. بنود خطة تدوير مفاتيح قاعدة البيانات (Staging DB Password Rotation Plan)

تم إعداد خطة التدوير الفنية وتحديد خطواتها التشغيلية والحدود المفروضة كالتالي:

* **المستخدم المستهدف بالتدوير (Target User):** `jumanasoft_staging_user`
* **قاعدة البيانات المستهدفة بالربط (Target DB):** `jumanasoft_staging`
* **لمس بيئة الإنتاج الفعلي:** **NO** ❌ (يُحظر اتصال أي خطوة ببيئة الإنتاج).
* **إجراء تدوير كلمة المرور القديمة:**
  * يتم تغيير كلمة المرور للمستخدم `jumanasoft_staging_user` في PostgreSQL إلى قيمة جديدة كلياً وغير مكشوفة.
* **تحديث ملف التهيئة المخصص للمرحلة:**
  * تحديث ملف التهيئة `.env.staging` على خادم الاختبار بالكلمة الجديدة.
  * **قاعدة الحماية:** يُحظر طباعة أو إفشاء القيمة الجديدة في تقارير المراجعة أو مستندات الدستور.
* **إعادة تشغيل التطبيق (Restart App Process):**
  * إعادة تحميل أو تشغيل عملية PM2 `jumanasoft-app-staging` لتطبيق الإعدادات الجديدة.
* **إثبات بطلان السر القديم وسريان الجديد:**
  * إثبات فشل الاتصال بالسر القديم ونجاحه بالجديد دون طباعتهما.
* **تنفيذ e47 وتفعيل بوابات الدفع:**
  * **لا (NO)**. معطل بالكامل وقت التشغيل.
