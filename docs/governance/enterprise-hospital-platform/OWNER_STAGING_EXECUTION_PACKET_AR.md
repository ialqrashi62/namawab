# حزمة تسليم وتفويض تشغيل بيئة الاختبار (Owner Staging Execution Packet)

* **المشروع:** منصة نما الطبية (NamaMedical ERP)
* **المرحلة:** تسليم واعتماد تجهيز بيئة الاختبار للمالك (PHASE_OWNER_STAGING_PROVISIONING_HANDOFF_AND_SIGNOFF)
* **الهدف:** توفير حزمة عمل متكاملة تحدد متطلبات التجهيز، والمحظورات الأمنية الصارمة، وتوزيع المسؤوليات بين فريق العمليات والتطوير والجودة لتهيئة بيئة الاختبار.

---

## 1. التزامات التجهيز المطلوبة من المالك والعمليات (Deliverables)

يجب على مالك النظام بالتنسيق مع مهندس العمليات (DevOps) توفير البنية التحتية التالية بشكل مستقل تماماً:
1. **استضافة معزولة (Isolated Host):** خادم افتراضي جديد (VM) أو حاوية (Container) معزولة مخصصة لبيئة الاختبار فقط.
2. **قاعدة بيانات منفصلة (Separate Database):** قاعدة بيانات PostgreSQL خالية باسم `nama_medical_staging`.
3. **مستخدم مقيد (Separate DB User):** مستخدم باسم `nama_staging_user` بصلاحيات حصرية ومقيدة لقاعدة بيانات الاختبار فقط.
4. **ملف بيئة مستقل (Separate Env File):** ملف تكوين مخصص `.env.staging` يتم حفظه وتأمينه بصلاحيات محدودة على خادم الاختبار.
5. **أسرار فريدة (Separate Secrets):** أسرار تشفير فريدة وغير مكررة لـ `SESSION_SECRET` و `JWT_SECRET`.
6. **عملية مستقلة (Separate PM2 Process):** تشغيل التطبيق تحت إدارة عملية PM2 مستقلة باسم `nama-app-staging`.
7. **نطاق فرعي مخصص (Staging Subdomain):** إعداد وتوجيه نطاق فرعي `staging.alfaisal-erp.com` مع شهادة أمان TLS فعالة.
8. **سجلات معزولة (Separate Logs):** حفظ سجلات الحركات والأخطاء في مسار مستقل للبيئة.
9. **نسخ احتياطي (Separate Backups):** إعداد وتفعيل جدولة النسخ الاحتياطي التلقائي لقاعدة بيانات الاختبار.

---

## 2. المحظورات الأمنية الصارمة (Strict Prohibitions)

> [!CAUTION]
> يُحظر تماماً وبشكل قاطع ارتكاب المخالفات الأمنية التالية أثناء تجهيز البيئة:
> * **يُمنع منعاً باتاً** استخدام بيانات اتصال أو مستخدم قاعدة بيانات الإنتاج الفعلي.
> * **يُمنع منعاً باتاً** نسخ أسرار ومفاتيح تشفير بيئة الإنتاج واستخدامها في بيئة الاختبار.
> * **يُمنع منعاً باتاً** نقل أو استيراد أي بيانات حقيقية للمرضى (PHI) إلى خادم الاختبار.
> * **يُمنع منعاً باتاً** تفعيل واجهات الربط الحقيقية مع منصة نفيس (NPHIES) أو هيئة الزكاة والجمارك (ZATCA).
> * **يُمنع منعاً باتاً** تشغيل أي ملفات ترحيل بيانات (Migrations) تؤثر على جداول الإنتاج.
> * **يُمنع منعاً باتاً** السماح للواجهات البرمجية بتنفيذ أي عمليات كتابة أو تعديل فعلية على الجداول الرئيسية.

## 3. مصفوفة المسؤوليات والأدوار (RACI Matrix)

| الدور الوظيفي | مسؤولية التجهيز (Accountable) | المهام الفنية المحددة (Specific Tasks) |
| :--- | :---: | :--- |
| **مالك النظام (Owner)** | المالك الرئيسي | توفير الميزانية، حجز الخوادم، تفويض حجز النطاق الفرعي، والتوقيع النهائي للاعتماد. |
| **مهندس العمليات (DevOps)** | منفذ التجهيز | إعداد الخادم، تهيئة جدار الحماية، إنشاء قاعدة بيانات ومستخدم الاختبار، ضبط PM2، وتثبيت شهادة SSL. |
| **المراجع الأمني (Security)** | مراجع ومصادق | فحص منافذ جدار الحماية، التأكد من عزل الأسرار، والتحقق من عدم وجود أي بيانات حقيقية للمرضى (PHI). |
| **مسؤول الجودة (QA)** | مراجع ومصادق | اختبار نقطة الصحة، فحص الاستجابات الوهمية وتوافقها مع العقود، وتأكيد حجب عمليات الكتابة. |
| **المطور الخلفي (Developer)** | داعم ومستشار | صيانة محرك المحاكاة، التأكد من إغلاق أعلام التكامل الحي في الكود، وتحديث عقود البيانات. |

---
**القرار التوجيهي:** تُسلم هذه الحزمة رسمياً للمالك لبدء التنفيذ، ويظل كود التطبيق معزولاً ومغلقاً لحين إعادة الأدلة.
