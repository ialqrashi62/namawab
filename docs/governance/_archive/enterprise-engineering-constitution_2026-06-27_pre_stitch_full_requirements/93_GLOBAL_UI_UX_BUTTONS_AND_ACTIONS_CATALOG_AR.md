## 1. الغرض

هذا الكتالوج يضمن أن كل شاشة وكل قسم وكل وحدة لها أزرار واضحة لا تنفذ فعلاً خطراً دون صلاحية وتدقيق.

## 3. قواعد تصميم الأزرار في STITCH

1. يجب ألا يكون الزر الخطر بلون أو نص غامض.
2. يجب أن تكون الأفعال النهائية مفصولة عن الحفظ كمسودة.
3. يجب أن يظهر سبب المنع عند عدم الصلاحية دون كشف أسرار.
4. يجب أن يُطلب السبب عند الإلغاء أو التعديل بعد الاعتماد.
5. يجب أن يظهر أثر الإجراء قبل تنفيذه في الإجراءات المالية والسريرية.
6. يجب أن يكون لكل زر test case.
7. يجب أن يربط كل زر audit_event.
8. يجب ألا يسمح زر واحد بتجاوز tenant أو role أو lock.

## 4. حالات كل زر

| الحالة | الوصف |
| --- | --- |
| enabled | المستخدم يملك الصلاحية والسياق مكتمل |
| disabled | السياق ناقص أو الشرط غير مكتمل |
| hidden | المستخدم لا يملك صلاحية معرفة وجود الإجراء |
| loading | الإجراء قيد التنفيذ |
| success | تم التنفيذ مع رسالة واضحة |
| error | فشل آمن دون stack trace |
| permission_denied | منع صلاحية دون كشف بيانات |
| locked | السجل مقفل ويتطلب amendment |
