# Phase 2 — قائمة تحقّق smoke مُصادَق للمشغّل (Operator Checklist)

> الغرض: إغلاق بوابة "smoke مُصادَق" المطلوبة قبل نشر RLS الإنتاجي للمجموعات A/B/C.
> الحالة: `AUTHENTICATED_SMOKE_OPERATOR_CHECKLIST_READY`. لا أملك بيانات اعتماد إنتاج/اختبار، وممنوع إنشاء مستخدمين اصطناعيين ⇒ يُنفِّذ المشغّل هذه القائمة ببيانات اعتماد صالحة.

## لماذا هذه القائمة
نشر RLS على جداول بيانات إنتاجية يتطلب إثبات أن المسارات المُصادَقة تُرجع **بيانات المستأجر الصحيحة (لا 0)** تحت RLS. 401 للمجهول مُثبت، لكنه لا يكفي. الأساس المعماري (pool مغلّف + AsyncLocalStorage) يجعل الكسر مستبعداً (42 جدولاً حياً)، لكن التأكيد المُصادَق يُغلق البوابة.

## الإعداد
- استخدم مستخدماً حقيقياً واحداً لكل مستأجر (مستأجر A ومستأجر B إن أمكن) ببيانات اعتماد صالحة. **لا تنشئ مستخدمين اصطناعيين في الإنتاج.**
- لا تكتب/تعدّل/تحذف سجلات إنتاج (قراءات فقط).
- نفّذ بعد تطبيق RLS لكل دفعة (A ثم B ثم C).

## خطوات لكل دفعة RLS (بعد التطبيق)
1. سجّل الدخول كمستخدم المستأجر A → احفظ الجلسة (cookie).
2. لكل جدول في الدفعة، نادِ مساره القرائي (أمثلة):
   - A: `/api/medical/records`, تقارير HR، `/api/insurance/claims`.
   - B: `/api/inventory/*`, مشتريات الصيدلية، الصيانة.
   - C: إعدادات/قوائم منسدلة تعتمد company_settings/facilities.
3. تأكّد: **HTTP 200 وبيانات غير فارغة** للمستأجر A (ليست 0 صفوف بسبب RLS).
4. كرّر بمستخدم المستأجر B → يرى بيانات B فقط.
5. تحقّق عدم وجود تسريب: A لا يرى صفوف B والعكس.
6. لا أخطاء 500 بسبب صلاحيات ناقصة.
7. خاص بـ C: تأكّد أن حارس استحقاق المنشأة ما زال يعمل (الصفحات الحساسة تُحمَّل لمنشأة مُهيّأة، وتُحجب لغير المستحقّ) — أي أن الصفوف العالمية (company_settings tenant_id IS NULL) ما زالت مرئية.

## معايير القبول
- كل مسارات الدفعة: 200 + بيانات المستأجر الصحيحة.
- لا تسريب عبر المستأجرين.
- لا 500 صلاحيات.
- حارس الاستحقاق سليم (للدفعة C).
⇒ عندها البوابة `AUTHENTICATED_SMOKE_PASS` وتُعتمد دفعة RLS الإنتاجية.

## عند الفشل
- 0 صفوف غير متوقّع لمستأجر صالح ⇒ مسار لا يضبط app.tenant_id ⇒ شغّل `rls_group_<X>_candidate_down.sql` للدفعة (أو أعد DB_USER=postgres مؤقتاً) ثم أصلح ربط السياق.
- 500 صلاحيات ⇒ منحة ناقصة ⇒ راجع منح nama_medical_app.

## البديل (Risk Acceptance)
بدلاً من القائمة، يمكن لصاحب القرار توثيق **قبول مخاطرة صريح** للاعتماد على الأساس المعماري (pool مغلّف، 42 جدولاً حياً تعمل) + الاسترجاع الفوري (down/DB_USER) — عندها تُعتمد دفعات RLS الإنتاجية بلا smoke مُصادَق.
```text
FINAL_STATUS: AUTHENTICATED_SMOKE_OPERATOR_CHECKLIST_READY
NEXT_REQUIRED_ACTION: operator runs checklist (or documents risk acceptance) => enables Phase 3 prod RLS batches
```
