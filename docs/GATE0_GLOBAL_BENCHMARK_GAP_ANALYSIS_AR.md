# تقرير Gate 0 — الجرد الشامل ومقارنة الفجوات مع الأنظمة العالمية
## NamaMedical / نظام الطبيب

**التاريخ:** 2026-07-02  •  **المنهج:** Auto Pilot Gate-by-Gate (قراءة وتحليل فقط — لا تعديل، لا DDL، لا نشر)
**نطاق المسح:** ستة أعناق أقسام عبر فرق استكشاف متوازية، مبني على الكود الفعلي (migrations + الوحدات + server.js).

> **إخلاء مهني:** التحليل السريري/الصيدلاني هنا لأغراض تحليل سير العمل والمتطلبات والسلامة والصلاحيات والتنبيهات داخل النظام فقط، وليس بديلاً عن طبيب أو صيدلي مرخّص.

---

## 1. البنية العامة (Baseline)

- **server.js أحادي بحجم 18,266 سطرًا** (monolith) + ~66 وحدة JS منطقية + 161 ملف اختبار.
- **229 ملف Migration** منظّمة على شكل Epics من e0 إلى e47 + ex_* + p0/p1_*.
- **قاعدة PostgreSQL بسياسة FORCE RLS** على مستوى المستأجر عبر `current_setting('app.tenant_id')` — نمط قانوني ومتسق في معظم الجداول.
- التشغيل بدور تطبيق غير مميّز (`nama_medical_app`, super=false, bypassrls=false) — إثبات عزل مثبت مسبقًا.

## 3. أبرز الفجوات المتقاطعة مقابل الأفضل عالميًا (Epic / Oracle Health-Cerner / Meditech) والمعايير

### 3.1 التشغيل البيني والترمينولوجي (الفجوة الأكبر إستراتيجيًا)
- **لا سطح FHIR R4/USCDI**: لا موارد Condition/Observation/MedicationRequest/AllergyIntolerance/DiagnosticReport للتصدير/التبادل.
- **لا ربط ترمينولوجي حقيقي**: الأكواد (ICD-10-AM/SNOMED CT/LOINC/SBS) مخزّنة كنص حر بلا تحقق/value sets/هرمية/terminology server.

### 3.2 سلامة المريض ونزاهة البيانات
- **درجات سريرية من العميل**: DAS28/GCS/NIHSS في التخصصات تُرسل كأرقام من العميل (قابلة للتزوير)، بخلاف نمط `ob_engine` الخادمي الصحيح.
- **لا EWS آلي مع تصعيد**: NEWS2 Scale-1 فقط؛ لا MEWS/PEWS، لا إنذار إنتان (qSOFA/SIRS)، لا تصعيد تلقائي، لا RRT/Code-Blue.
- **حلقة الأوامر↔النتائج مفتوحة**: التوجيه بين الأقسام stub، لا إقرار نتائج حرجة (result acknowledgement) على مستوى الطبيب.
- **CDS محدود**: لا جرعات حسب الوزن/العمر/الكلى/الكبد، لا duplicate-therapy-class، مصفوفة تفاعلات مكوّدة يدويًا.

### 3.3 عزل المستأجرين والأمن (Defense-in-depth)
- **ثقة ترويسة `x-tenant-id` قبل الجلسة** (server.js:417 و tenant_middleware يفترض tenant=1) — RLS + requireTenantScope هما الحاجز الوحيد.
- **جداول e21 السريرية بلا RLS + تعارض مخطط**: `clinical_departments` بلا `tenant_id` بينما الكود يستعلم به مع `ON CONFLICT(code)` عالمي → تصادم عبر المستأجرين.
- **stubs e30–e46 بلا FK إلى tenants**، والأسنان `tenant_id` عبر ALTER nullable backfilled=1 وربما بلا FORCE RLS.
- **تعارضات مخطط**: e46 يعيد إنشاء `obgyn_pregnancies` رقيق يصطدم بـe14 الغني؛ e43 يكرر `eye_exams` الخاص بـe38.

### 3.4 الامتثال السعودي (NPHIES / ZATCA / CCHI / CBAHI)
- **NPHIES**: عميل حقيقي لكنه gated؛ الحزم FHIR يدوية غير مطابقة لبروفايلات KSA (لا MessageHeader، نوع Bundle=collection لا message، لا امتدادات KSA/SBS/ICD-10-AM، لا تحليل استجابة — التسوية يدوية).
- **ZATCA**: التوقيع التشفيري حقيقي، لكنه **غير مُضمَّن في UBL** (`cac:Signature`=placeholder، لا XAdES/SignedProperties، لا C14N فعليّة)؛ Phase-1 وPhase-2 في وحدتين (خطر انحراف).
- **CCHI/CBAHI/JCI**: قواعد التأمين والاعتماد غير مُرمّزة.

### 3.5 دورة الإيراد المالية (RCM)
- **حلقة الرسوم→المطالبة→التحصيل→GL مفتوحة/يدوية**: `post-to-ar` يقلب أعلامًا فقط **ولا يُنشئ قيد يومية فعلي** (GL تجميلي)؛ المطالبات تُنشأ بإدراج يدوي.
- **غياب idempotency** في تقديم المطالبة/ZATCA/التحصيل (خطر تكرار/ازدواج).
- لا نمذجة عقود دافعين/underpayment/denial worklist/patient statements.

### 3.6 عمق الأقسام مقابل المتخصصين العالميين
- **الأسنان** أدنى بكثير من Open Dental/Dentrix (لا odontogram/perio 6-point/tx-plan).
- **الأطفال** بلا حساب percentile (WHO/CDC) ولا محرك استحقاق تطعيم مربوط بالسجلات.
- **العلاج الطبيعي** بلا أدوات مقننة (FIM/Berg/Oswestry/TUG).
- **e31–e46** جداول التقاط بيانات لا flowsheets/order-sets/CDS.
- **التخدير** بلا سجل داخل-عملياتي آلي؛ **التمريض** بلا flowsheet منظّم.

### 3.7 المؤسسة والمنصة
- **HR**: لا نهاية خدمة (EOS)، لا WPS/Mudad، لا حصة GOSI صاحب العمل، لا أرصدة إجازات، لا ATS/onboarding/offboarding.
- **المخزون**: reorder_point موجود بلا مولّد إعادة طلب تلقائي؛ لا ماستر موردين/consignment/ABC.
- **SaaS**: الصلاحيات fail-OPEN observe-only، max_users فقط مُوصّل؛ لا عداد استخدام/تسجيل ذاتي/فوترة مستأجرين.
- **RBAC**: نظامان متوازيان (in-code + DB) خطر انحراف؛ لا هرمية/break-glass/SoD.
- **Audit**: لا التقاط before/after في الوسيط، لا سلسلة تجزئة مانعة للعبث على `audit_trail`.
- **بوابة المريض**: لا دخول ذاتي/دفع/مواعيد ذاتية/e-consent.

## 4. خارطة المراحل المقترحة (Prioritized Waves)

الترتيب حسب: **سلامة المريض → عزل/أمن → امتثال تنظيمي → عمق أقسام → مؤسسة**. كل Gate = أصغر تغيير آمن + اختبارات، بلا لمس Production وبلا DDL إلا حين تسمح المرحلة صراحة (المسارات التي تتطلب DDL تُسلَّم كـ **candidates** جاهزة للاعتماد، لا تُنفَّذ).

### الموجة 1 — سلامة المريض ونزاهة البيانات (كود فقط، بلا DDL)
- **G1**: محرك درجات سريرية خادمي `specialty_scores.js` (DAS28، NIHSS، GCS، إلخ) — منع تزوير العميل، على نمط `ob_engine`.
- **G2**: محرك EWS آلي (MEWS/PEWS + إنذار إنتان qSOFA/SIRS) + قواعد تصعيد.
- **G3**: إغلاق حلقة الأوامر↔النتائج + إقرار النتائج الحرجة.

### الموجة 2 — العزل والأمن (كود + candidates DDL)
- **G4**: تصحيح ثقة ترويسة `x-tenant-id` قبل الجلسة (كود، defense-in-depth).
- **G5**: RLS + FK + تصحيح مخطط جداول e21 والـstubs (DDL candidates).
- **G6**: حل تعارضات المخطط (e46 obgyn، e43/e38 عيون) (DDL candidates).
- **G7**: idempotency للمطالبات/ZATCA/التحصيل (كود + candidate).

### الموجة 3 — الامتثال السعودي
- **G8**: مطابقة حزم NPHIES لبروفايلات KSA (message Bundle، MessageHeader، امتدادات، SBS/ICD-10-AM).
- **G9**: تضمين توقيع ZATCA في UBL (XAdES/SignedProperties + C14N) وتوحيد Phase-1/2.
- **G10**: إغلاق دورة الإيراد charge→claim→remittance→GL (قيد يومية آلي حقيقي).

### الموجة 4 — عمق الأقسام إلى تكافؤ عالمي
- **G11**: الأسنان — odontogram + perio charting + treatment plan.
- **G12**: الأطفال — مخططات نمو WHO/CDC مرسومة + محرك استحقاق تطعيم.
- **G13**: العلاج الطبيعي — أدوات مقننة (FIM/Berg/Oswestry/TUG).
- **G14**: تعميق stubs التخصصات → flowsheets/order-sets.
- **G15**: التمريض — flowsheets منظّمة (head-to-toe, LDAs, wounds).
- **G16**: التخدير — سجل داخل-عملياتي + معايير خروج PACU.
- **G17**: المختبر/الأشعة — تكامل أجهزة ثنائي + DICOM حقيقي + LOINC master.
- **G18**: بوابة المريض — دخول ذاتي + دفع + مواعيد ذاتية + e-consent.

### الموجة 5 — المؤسسة والتشغيل البيني
- **G19**: HR — نهاية الخدمة + WPS/Mudad + GOSI صاحب العمل + أرصدة إجازات.
- **G20**: المخزون — PAR/auto-reorder + ماستر موردين.
- **G21**: SaaS — تفعيل صلاحيات fail-closed + عداد استخدام + فوترة مستأجرين.
- **G22**: Audit — before/after diff + سلسلة تجزئة مانعة للعبث.
- **G23**: سطح FHIR R4 عام + terminology server.

---

## 5. القرار

**Gate 0 = ناجح** (جرد + مقارنة + خارطة). الانتقال التلقائي إلى **Gate 1** (محرك الدرجات السريرية الخادمي) — أصغر تغيير آمن، بلا DDL، قابل للاختبار فورًا، ويغلق فجوة سلامة/نزاهة حقيقية رصدها المسح.

**لم يُلمس أي شيء في Production. لم يُنفَّذ أي DDL/Migration/Deploy.**
