## 2. الاختبارات الناقصة (الفجوات)

| النوع | الحالة | الأولوية |
| ----- | ------ | -------- |

## 3. أخطر السيناريوهات غير المغطاة

1. **تسريب بيانات بين مستأجرين عبر الموديولات الحديثة** (السجلات الطبية/التأهيل/البوابة/الصيدلية السريرية/التغذية) — لا اختبار يكشفه حالياً. **P0**.
2. **استعادة DB من المصدر تُسقط RLS** — لا اختبار يتحقق من بقاء RLS بعد إعادة البناء.
3. **CSRF عبر النطاقات** (مع `CORS origin:true`) — غير مُختبر.
4. **سلوك التطبيق عند فشل Redis في الإنتاج** — موثّق نظرياً (`process.exit`) لكن غير مُختبر آلياً.
5. **حدود الخصم على مستوى API** (تُفرض على الواجهة فقط) — غير مُختبر خلفياً.

---

## 4. خطة QA عالمية مقترحة

1. **إطار اختبار رسمي**: تبنّي Jest + هيكلة `npm test`.
2. **CI Pipeline**: GitHub Actions يشغّل كل `cross_tenant_*` + الاختبارات الجديدة عند كل push.
3. **سد فجوة P0**: كتابة `cross_tenant_{medical_records,clinical_pharmacy,rehab,portal,dietary}_test.js`.
4. **Unit + Integration**: بعد استخراج service layer (Gate 4).
5. **Security suite**: IDOR/authz/CSRF/XSS مؤتمتة.
6. **E2E browser**: Playwright لأهم التدفقات (دخول، تسجيل مريض، موعد، فاتورة، صرف دواء).
7. **Load/restore drills**: مجدولة دورياً.

## 5. سيناريوهات UAT لكل قسم (عيّنة)

| القسم | سيناريو UAT أساسي |
| ----- | ----------------- |
| الاستقبال | تسجيل مريض جديد → بحث → فتح ملف |
| المواعيد | حجز → تعارض → check-in → no-show |
| الطبيب | استدعاء مريض من الطابور → تشخيص → طلب مختبر/أشعة → وصفة |
| المختبر | استقبال طلب → إدخال نتيجة → اعتماد → طباعة |
| الصيدلية | استقبال وصفة → صرف → خصم مخزون → فحص تفاعل |
| المالية | إنشاء فاتورة → دفع جزئي → استرداد → ZATCA QR |
| التنويم | إدخال → جولة → نقل سرير → إفراغ |
| الطوارئ | تسجيل زيارة → فرز triage → علامات حيوية عاجلة |
| العزل (لكل موديول) | مستخدم مستأجر A لا يرى بيانات مستأجر B (403/0 rows) |
