# تقرير جاهزية التراجع السريع عند الطوارئ للإنتاج (Cutover Rollback Readiness Report)
## نظام نما الطبي (NamaMedical) - مرحلة التنفيذ والعبور للإنتاج

يوثق هذا التقرير الجاهزية الفنية والخطوات المتبعة للتراجع السريع واستعادة الحالة المستقرة السابقة للنظام في حال حدوث أي فشل غير متوقع أثناء عملية العبور.

## 1. تفاصيل الالتزام المستقر السابق (Previous Stable State)

* **الالتزام المستقر السابق (Previous Stable Commit)**: `ae07f6f9de8a2a9b48c9f62acea556d98cba1ec0`

---

## 2. إجراءات التراجع الفنية (Rollback Steps)

في حال حدوث أي فشل في تشغيل التطبيق أو سقوط الخدمات الطبية، سيتم تنفيذ الخطوات التالية فوراً:

### الخطوة 1: إيقاف الخدمات الحالية
إيقاف خادم الويب تحت PM2 لتحرير الموارد ومنع الاستجابة للطلبات غير المستقرة:
```bash
npx pm2 stop nama-web
```

### الخطوة 2: التراجع عن تعديلات الـ RLS وترقية قاعدة البيانات
إلغاء وتجميد سياسات الـ RLS التي تم إدخالها للتأكد من عودة قاعدة البيانات لحالتها الطبيعية:
```bash
psql -U postgres -d nama_medical_web -f docs/sql/production_readiness_force_rls_down.sql
```

### الخطوة 3: استعادة قاعدة البيانات من النسخة الاحتياطية
في حال وجود أخطاء في تكامل البيانات، يتم استعادة النسخة الاحتياطية الكاملة الملتقطة مباشرة قبل بدء العبور:
```bash
pg_restore -U postgres -d nama_medical_web --clean --verbose local_backups/nama_medical_prod_before_cutover.bak
```

### الخطوة 4: التراجع عن رموز الكود البرمجي
الرجوع بمستودع الكود الأب والفرعي إلى الالتزام المستقر السابق:
```bash
git checkout ae07f6f9de8a2a9b48c9f62acea556d98cba1ec0
git submodule update --init --recursive
```

### الخطوة 5: إعادة تشغيل الخدمة والفحص
إعادة بدء تشغيل خادم الويب وفحص استجابة الواجهة:
```bash
npx pm2 start nama-web
curl.exe -i http://localhost:3000/api/health
```

- ملف النسخة الاحتياطية `nama_medical_prod_before_cutover.bak` سليم بالكامل وموثق وقابل للاستعادة الفورية بنسبة 100%.
