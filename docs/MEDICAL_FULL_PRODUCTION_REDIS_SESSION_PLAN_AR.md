# خطة تشغيل خادم Redis وتوزيع الجلسات في الإنتاج (Redis and Session Production Plan)
## نظام نما الطبي (NamaMedical) - مرحلة التخطيط للترقية والعبور للإنتاج

توثق هذه الخطة المعايير التشغيلية والسياسات الأمنية لإلزامية تشغيل خادم Redis لإدارة وتوزيع الجلسات في بيئة الإنتاج الكامل، وحظر استخدام متجر الذاكرة الافتراضي MemoryStore.

---

### 1. إلزامية Redis وحظر متجر الذاكرة (Mandatory Redis Policy)

1. **السياسة الأمنية الصارمة**:
   - يُمنع منعاً باتاً استخدام متجر الذاكرة الافتراضي `MemoryStore` في بيئة الإنتاج الكامل.
   - تبرير الحظر الفني:
     - تطبيق الويب في بيئة الإنتاج مصمم للتشغيل خلف خادم توزيع حمل (Load Balancer) بنسخ متعددة (Multi-Node / Cluster). استخدام `MemoryStore` سيؤدي إلى فقدان الجلسات وتشتتها بين النسخ المختلفة ومطالبة المستخدمين بتسجيل الدخول مراراً وتكراراً.
     - افتقار الـ `MemoryStore` للميزات الأمنية وقابلية التوسع وخطورته في تسريب الذاكرة (Memory Leaks).
2. **شروط الاتصال الإجباري بـ Redis**:
   - لا يمكن لتطبيق الويب أن يبدأ بنجاح دون وجود اتصال نشط وموثق بخادم Redis.
   - في حال غياب الاتصال بـ Redis عند بدء التشغيل، يجب أن يتوقف خادم التطبيق فوراً عن العمل ويعيد رمز خطأ (Crash on Startup) لإرشاد المهندسين.

---

### 2. معايير تأمين وتشغيل خادم Redis (Redis Security & Configurations)

1. **التحقق من الهوية والتشفير (Auth & TLS)**:
   - فرض استخدام كلمة مرور قوية لتأمين خادم Redis يتم قراءتها فقط من متغيرات البيئة الآمنة `REDIS_PASSWORD`.
   - تشفير قنوات الاتصال بين تطبيق الويب وخادم Redis باستخدام بروتوكول TLS.
2. **الاستقرار والحفظ الدائم (Availability & Persistence)**:
   - تمكين خاصية الحفظ الدائم لبيانات الجلسات (Redis Persistence) عبر تفعيل خيار `appendonly yes` لضمان عدم ضياع جلسات المرضى والكوادر الطبية عند إعادة تشغيل خادم Redis.
   - تهيئة سياسة الاستبعاد لتكون `noeviction` أو `volatile-lru` لضمان عدم حذف الجلسات الفعالة عشوائياً عند امتلاء الذاكرة.

---

### 3. سياسة التوقف الصارم عند الأعطال (Redis STOP-THE-LINE Policy)

في حال حدوث انقطاع مفاجئ للاتصال بخادم Redis أثناء تشغيل النظام في الإنتاج:
1. **رفض التراجع الصامت (No Silent Fallback)**:
   - يُمنع تراجع التطبيق تلقائياً وصامتاً إلى ميزتي `MemoryStore` أو `Local Memory`.
2. **إيقاف قبول وإنشاء الجلسات (Block Session Creation)**:
   - يجب إرجاع استجابة بالخطأ الفوري (HTTP 503 Service Unavailable) لجميع العمليات الجديدة التي تتطلب جلسات.
   - رفض طلبات تسجيل الدخول بالكامل وإلغاء صلاحية الوصول الحالية لضمان عدم معالجة الطلبات الطبية خارج سياق عزل المستأجرين الآمن.
3. **تنبيه المهندسين الفوري**:
   - إطلاق جرس إنذار فوري عالي الأهمية (Critical Alert) لفريق عمليات النظام يشير إلى انقطاع خادم Redis لتنفيذ التدخل البشري العاجل.

---

### 4. معايير إدارة عمر الجلسات ومراقبتها (Session Lifecycle & Monitoring)

1. **إدارة عمر الجلسة (Session Lifespan)**:
   - تحديد الحد الأقصى لصلاحية الجلسة بـ `24 ساعة` (Session TTL = 24h).
   - تفعيل عمر الخمول للجلسة (Idle Timeout) بـ `ساعتين` كحد أقصى (Max Idle = 2h)، يتم بعدها تسجيل خروج المستخدم تلقائياً وتدمير ملف الجلسة لحماية المحطات الطبية.
2. **رصد الأداء والمؤشرات**:
   - مراقبة خادم Redis بشكل مستمر للتحقق من:
     - زمن التأخير (Latency): يجب أن يبقى أقل من `5 مللي ثانية`.
     - استهلاك الذاكرة (Memory Usage): إصدار تنبيه عند بلوغ استهلاك ذاكرة Redis لـ 80% من الحجم المتاح.
     - عدد الاتصالات النشطة (Connected Clients).
