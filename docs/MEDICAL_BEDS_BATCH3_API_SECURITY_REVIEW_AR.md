# تقرير مراجعة أمن النهايات البرمجية - الدفعة الثالثة (Batch 3 API Security Review)
## نظام نما الطبي (NamaMedical) - بيئة Staging

يوثق هذا التقرير التدقيق الأمني التفصيلي للنهايات البرمجية (API Routes) المرتبطة بعمليات خروج المرضى وتحديثات الأسرة وإشغالها للتأكد من خلوها من الثغرات الأمنية مثل تجاوز الصلاحيات (IDOR) وتداخل مستأجرين مختلفين.

---

### 1. تدقيق نهايات خروج المرضى (Discharge Endpoints Audit)

#### المسار المستهدف: `PUT /api/admissions/:id/discharge`
* **الحماية المطبقة:** `requireAuth`, `requireTenantScope`.
* **التحقق من الهوية والأثر (Credential Context):**
  * يتم الحصول على `tenantId` من الجلسة الآمنة `getRequestTenantContext(req)` ويُحظر تماماً الاعتماد على معرف المستأجر من جسم الطلب (Request Body).
* **منع ثغرة الـ IDOR:**
  * يتم إجراء استعلام تحقق مسبق للتأكد من ملكية حركة التنويم قبل التحديث:
    `SELECT id, bed_id, patient_id FROM admissions WHERE id = $1 AND tenant_id = $2`
  * إذا لم يكن التنويم تابعاً للمستأجر، يرجع النظام رمز `404 Not Found` فوراً.
* **تحديثات الجداول المتتابعة:**
  1. تحديث `admissions` بـ `tenant_id = $10`.
  2. تحديث `beds` بـ `tenant_id = $2`.
  3. تحديث `patients` بـ `tenant_id = $2`.
  * **تقييم الأمان:** ممتاز ومحمي بنسبة 100%. خروج المريض يحرر سريره ومريضه أمنياً ضمن حدود المنشأة فقط.

---

### 2. تدقيق نهايات حساب إشغال الأسرة والإحصاء (Census Endpoints Audit)

#### المسار المستهدف: `GET /api/beds/census`
* **الحماية المطبقة:** `requireAuth`, `requireTenantScope`.
* **التحقق وعزل الاستعلامات:**
  * يستعلم الأجنحة (`wards`) والأسرة (`beds`) ويضم التنويم النشط (`admissions`) مفلترة بالكامل بـ `tenant_id`:
    `WHERE b.tenant_id = $1`
* **منع تسريب مؤشرات الأداء (KPI Data Leak):**
  * تمنع التصفية وحماية RLS العميقة في الجداول الثلاثة أي إمكانية لتسريب مؤشرات سعة مستأجر آخر أو نسبة إشغاله الحقيقية.

---

### 3. تحليل المخاطر والثغرات المحتملة (Vulnerability Assessment)

| مهدد أمني (Threat) | تقييم الخطر | الضابط الوقائي الحالي | حالة الحظر (Status) |
| :--- | :---: | :--- | :---: |
| **تجاوز ملكية حركة التنويم (IDOR)** | **HIGH** | التحقق من التنويم بـ `tenant_id` من الجلسة قبل معالجة التحديث. | **BLOCKED** |
| **تحرير سرير مستأجر آخر** | **HIGH** | تضمين فلتر `tenant_id` في استعلام UPDATE الموجه لجدول `beds`. | **BLOCKED** |
| **قراءة سعة أجنحة منشأة أخرى** | **MEDIUM** | RLS مفروض على جدول `wards` و `beds` لفرز السجلات تلقائياً. | **BLOCKED** |
| **تحديث حالة مريض منشأة أخرى** | **HIGH** | تضمين فلتر `tenant_id` في استعلام UPDATE لجدول `patients`. | **BLOCKED** |

---

### 4. الخلاصة والقرار الأمني للنهايات (Audit Decision)
* **تقييم أمن الـ API:** `PASS`
* **مستوى أمان الجلسات وسياق المستأجر:** ممتاز ومطابق لمعايير الحماية الصارمة للمشروع.
* **القرار:** النهايات البرمجية الحالية محصنة تماماً وجاهزة لربطها بأمان مع سياسات RLS وقنوات العزل دون الحاجة لأي تعديلات برمجية إضافية.
