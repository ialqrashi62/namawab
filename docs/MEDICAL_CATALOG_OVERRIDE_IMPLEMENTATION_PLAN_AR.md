# خطة تنفيذ نظام تخصيص الكتالوجات الطبية (Implementation Plan)
## نظام نما الطبي (NamaMedical) - بيئة Staging

يوثق هذا التقرير خطة العمل الكاملة والخطوات المتبعة لتطبيق نظام تخصيص أسعار الكتالوجات والخدمات الطبية لكل مستأجر.

### 1. الأهداف والنطاق
- **الهدف**: تمكين المستأجرين (عيادات أو مستشفيات مختلفة) من تحديد أسعار مخصصة وقوالب تقارير خاصة بهم للتحاليل والأشعة والخدمات الطبية دون تكرار أو تعديل الكتالوجات العالمية المشتركة.
- **الجداول المستهدفة**: 
  - `lab_tests_catalog`
  - `radiology_catalog`
  - `medical_services`
- **البيئة**: Staging فقط (`STAGING_ONLY`).

### 2. مراحل التنفيذ
1. **النسخ الاحتياطي**: أخذ نسخة فيزيائية كاملة من قاعدة البيانات قبل تشغيل أي تعديلات.
2. **الـ DDL والـ SQL Migrations**: إنشاء وتطبيق جداول التخصيص وإعداد RLS والسياسات المناسبة لكل جدول.
3. **تعديل كود قاعدة البيانات**: تعديل ملف `namaweb/db_postgres.js` لإنشاء الجداول والقيود تلقائياً عند بدء تشغيل الخادم.
4. **تحديث مسارات الـ API**:
   - إصلاح مسارات الكتالوج المكررة والتالفة في `namaweb/server.js`.
   - دمج جداول التخصيص عبر `LEFT JOIN` في مسارات القراءة لضمان استلام الأسعار المحدثة.
   - استقبال وتخزين تحديثات الأسعار في جداول التخصيص بدلاً من الجداول العالمية.
   - تحديث مسارات إنشاء الطلبات (`POST /api/lab/orders`, `POST /api/radiology/orders`) للبحث في التخصيصات أولاً.
5. **الاختبار والتحقق**: تشغيل اختبار الدخان والتحقق من العزل RLS وسلامة العمليات والـ UI.

### 3. معايير القبول والأمان
- نجاح كامل الاختبارات لـ RLS دون تسريب أي بيانات.
- عدم تكرار أسطر الكتالوج المشترك.
- عدم كشف أسعار مستأجر لمستأجر آخر.
- عدم وجود أي كلمات مرور أو مفاتيح سرية في السجلات والتقارير.
