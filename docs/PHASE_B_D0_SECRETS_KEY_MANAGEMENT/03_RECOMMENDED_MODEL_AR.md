# D0 — النموذج الموصى (للقرار، لا تنفيذ)

> توصية هندسية. القرار النهائي للمالك (`OWNER_SELECT_KEY_MODEL`). لا يُنشأ أي مفتاح هنا.

## التوصية: Option E (هجين) — Envelope encryption بمزوّد KEK قابل للتبديل
لهذا النشر (صندوق win32 واحد، on-prem، بلا سحابة حالياً)، الأنسب نموذج يفك الحجب **فوراً** ويحفظ مساراً للأقوى:

```text
طبقة تشفير موحّدة:
  DEK (AES-256-GCM، 32 بايت) يشفّر البيانات (mfa_secret / ملفات PHI / النسخ / أسرار التكامل)
  KEK (مفتاح رئيس) يغلّف الـDEK
  مزوّد KEK خلف واجهة مجرّدة (getKEK / wrap / unwrap):
    - المرحلة 1 (الآن): Option B (DPAPI) إن قُبلت الوحدة الأصلية، وإلا Option A (ملف مفتاح مقيّد مستثنى من النسخ)
    - المرحلة 2 (لاحقاً): Option D (Vault) أو C (KMS) دون إعادة تشفير البيانات — فقط re-wrap للـDEK
```

## لماذا E وليس واحداً صرفاً
- **A وحده**: يعمل الآن لكنه أضعف (تواجد مشترك) وبلا مسار ترقية واضح.
- **B وحده**: جيد محلياً لكن machine-bound يعقّد DR/الهجرة.
- **C وحده**: قوي لكن يفرض تبعية سحابة على نظام on-prem (توفّر/شبكة).
- **D وحده**: الأقوى on-prem لكنه عبء تشغيلي كبير للبدء.
- **E**: يأخذ خفّة A/B الآن + قوة D/C لاحقاً، مع تجريد يمنع القفل المعماري. التطبيق أصلاً يملك `crypto` المدمج ⟶ طبقة AES-256-GCM بلا تبعية جديدة.

## تخصيص حسب نوع السرّ
| السرّ | المرحلة 1 (الآن) | الهدف (المرحلة 2) |
|---|---|---|
| `mfa_secret` (A3) | DEK مغلّف بـKEK (B/A) | Vault/KMS |
| ملفات PHI (`phi_vault`) | DEK لكل ملف، AES-256-GCM | Vault/KMS |
| المفتاح الخاص ZATCA CSID | **يفضّل Vault/HSM**؛ sandbox فقط على ملف/DPAPI مؤقتاً | **Vault/HSM (D)** |
| شهادات NPHIES (mTLS) | مخزن مقيّد + KEK | Vault/HSM |
| تشفير النسخ offsite | DEK للنسخ، KEK محمي | KMS/Vault |
| اعتمادات تكامل مستقبلية | ملف مقيّد/مزوّد KEK | Vault/KMS |

> ملاحظة امتثال: المفاتيح الخاصة التنظيمية (ZATCA CSID، NPHIES) في الإنتاج **يُفضّل بشدّة Vault/HSM**؛ الملف/DPAPI مقبول لبيئات sandbox فقط.

## مبادئ ثابتة (كل الخيارات)
- لا مفتاح/سرّ في Git أو `.env` داخل المستودع؛ لا طباعة؛ ACL مقيّد؛ فصل sandbox/production؛ تدوير مخطّط؛ تدقيق الاستخدام؛ **escrow آمن للـKEK** (نسخة استرداد منفصلة) لتفادي فقدان البيانات.
- استثناء مفتاح/ملفات المفاتيح من مجموعة النسخ الاحتياطي.

## القرار المطلوب من المالك
1. الموافقة على **E (هجين)** كإطار، و
2. اختيار **مزوّد KEK للمرحلة 1**: **B (DPAPI)** أم **A (ملف مفتاح)**، و
3. تأكيد ما إن كان هناك مسار لـ**Vault/KMS** للمرحلة 2 (للمفاتيح التنظيمية).

عند الاختيار، تبدأ بوابة تنفيذ منفصلة (backup → rehearsal → طبقة التشفير → تحقّق) لـA3 أولاً، ثم تفك حجب ZATCA/NPHIES.
