# D0 — خيارات إدارة المفاتيح (مقارنة A–E)

> تحليل ورقي فقط. لا إنشاء مفاتيح، لا تغيير. كل الخيارات تفترض **envelope encryption**: مفتاح بيانات (DEK) AES-256-GCM يشفّر البيانات، ومفتاح رئيس (KEK) يحمي الـDEK — والخيارات تختلف في **أين يُحفظ/يُحمى الـKEK**.

## Option A — ملف مفتاح خارجي مقيّد خارج المستودع والنسخ
- **Security strength**: متوسطة. المفتاح ملف على نفس الصندوق؛ يحمي ضد سرقة نسخة DB/repo فقط إن **استُثني من النسخ** ووُضع على مسار/قرص منفصل.
- **Operational complexity**: منخفضة جداً (يطابق نمط `nama_medical_app_db_password`).
- **Backup/restore impact**: يجب استثناء الملف من النسخ؛ والاحتفاظ بنسخة آمنة منفصلة منه (escrow) وإلا فقدان المفتاح = فقدان البيانات المشفّرة.
- **On-prem suitability**: ممتازة (يعمل الآن، بلا اعتماد خارجي).
- **Cloud dependency**: لا.
- **Rotation support**: يدوي (تدوير KEK = إعادة تغليف الـDEKs؛ ممكن لكن يدوي).
- **Auditability**: ضعيفة (وصول الملف عبر ACL/تدقيق نظام الملفات فقط).
- **Failure mode**: فقدان الملف ⟶ فقدان فكّ التشفير؛ سرقة القرص الكامل (مع الملف) ⟶ انكشاف.
- **Recommended uses**: مرحلة انتقالية / sandbox / صناديق صغيرة بلا KMS.
- **Risks**: التواجد المشترك مع البيانات؛ نسيان استثنائه من النسخ.

## Option B — Windows DPAPI
- **Security strength**: متوسطة–عالية على الصندوق. المفتاح الرئيس يديره نظام التشغيل (مشتق من سياق المستخدم/الجهاز)، لا يخزّنه التطبيق ولا يدخل Git/النسخ.
- **Operational complexity**: منخفضة–متوسطة (وحدة `win-dpapi` الأصلية أو استدعاء PowerShell `ProtectedData`).
- **Backup/restore impact**: **حسّاس**: DPAPI (user/machine scope) **مربوط بالجهاز/الحساب** ⟶ استعادة على جهاز آخر تفقد فكّ التشفير ما لم تُدار مفاتيح الاسترداد؛ يعقّد الهجرة/التعافي من الكوارث.
- **On-prem suitability**: جيدة جداً لصندوق Windows ثابت.
- **Cloud dependency**: لا.
- **Rotation support**: عبر إعادة الحماية (re-protect)؛ يدوي.
- **Auditability**: محدودة (سجلّات نظام التشغيل).
- **Failure mode**: تلف ملف تعريف المستخدم/تغيّر الجهاز ⟶ فقدان الوصول؛ يلزم خطة استرداد.
- **Recommended uses**: حماية KEK محلياً دون ملف مفتاح صريح؛ صندوق Windows مستقر.
- **Risks**: machine-bound (هجرة/DR)؛ تبعية وحدة أصلية أو shell-out في مسار حسّاس.

## Option C — KMS سحابي (AWS KMS / Azure Key Vault / GCP KMS)
- **Security strength**: عالية (مفاتيح مدعومة HSM، لا تغادر KMS؛ عمليات تشفير/فكّ عبر API).
- **Operational complexity**: متوسطة (SDK + IAM + شبكة).
- **Backup/restore impact**: ممتاز (المفتاح مستقل عن نسخ البيانات؛ النسخ تبقى مشفّرة وآمنة).
- **On-prem suitability**: متوسطة (يتطلب **اتصالاً سحابياً موثوقاً** من صندوق on-prem؛ انقطاع الشبكة = تعذّر فكّ التشفير).
- **Cloud dependency**: **نعم (عالية)** — حساب + اتصال + تكلفة.
- **Rotation support**: مدمج (تدوير تلقائي + إصدارات مفاتيح).
- **Auditability**: ممتازة (CloudTrail/Key Vault logs لكل استخدام).
- **Failure mode**: انقطاع الشبكة/الحساب ⟶ توقّف فكّ التشفير (يلزم cache/grace).
- **Recommended uses**: حين تتوفّر سحابة؛ التكاملات التنظيمية طويلة الأمد.
- **Risks**: تبعية وتوفّر السحابة لنظام on-prem؛ تكلفة؛ زمن وصول.

## Option D — Vault / HSM (on-prem)
- **Security strength**: عالية جداً (HashiCorp Vault أو HSM مادي؛ حفظ/توقيع داخل الحدود الآمنة).
- **Operational complexity**: **عالية** (خادم Vault: unseal، HA، نسخ، ترقيات؛ HSM: عتاد + تكلفة).
- **Backup/restore impact**: قوي (مفاتيح معزولة عن البيانات)؛ لكن يجب تشغيل/تأمين Vault نفسه.
- **On-prem suitability**: ممتازة (الأقوى on-prem، خاصة للمفاتيح الخاصة لـZATCA/NPHIES).
- **Cloud dependency**: لا (إن كان Vault/HSM محلياً).
- **Rotation support**: مدمج وغني.
- **Auditability**: ممتازة (audit devices في Vault).
- **Failure mode**: تعطّل Vault/فقد unseal keys ⟶ توقّف؛ يتطلب تشغيلاً ناضجاً.
- **Recommended uses**: نضج إنتاجي، مفاتيح خاصة تنظيمية، عدة تكاملات.
- **Risks**: عبء تشغيلي/خبرة؛ HSM تكلفة عتاد.

## Option E — نموذج هجين (envelope + مزوّد KEK قابل للتبديل)
- **الفكرة**: طبقة تشفير موحّدة (AES-256-GCM للـDEKs) خلف **واجهة مزوّد KEK مجرّدة**؛ يبدأ المزوّد بـ**B (DPAPI) أو A (ملف)** الآن، ويُبدَّل لاحقاً إلى **D (Vault) أو C (KMS)** دون إعادة هندسة البيانات المشفّرة (إعادة تغليف الـDEK فقط).
- **Security strength**: متوسطة الآن، قابلة للترقية لعالية.
- **Operational complexity**: منخفضة بدءاً، تنمو عند الترقية.
- **Backup/restore impact**: محكوم (الـDEK مغلّف؛ ترقية الـKEK = re-wrap).
- **On-prem suitability**: ممتازة (يعمل الآن، ومسار واضح للأقوى).
- **Cloud dependency**: لا (حتى تختار C).
- **Rotation support**: عبر المزوّد + إعادة تغليف الـDEK.
- **Auditability**: حسب المزوّد (تتحسّن مع Vault/KMS).
- **Failure mode**: حسب المزوّد الحالي؛ التجريد يقلّل خطر القفل المعماري.
- **Recommended uses**: **هذا النشر بالضبط** — يفك الحجب فوراً مع مسار ترقية.
- **Risks**: انضباط هندسي في طبقة التجريد؛ توثيق re-wrap.

## ملخّص المقارنة
| الخيار | القوة | التعقيد | ملاءمة on-prem | تبعية سحابة | الأنسب لـ |
|---|---|---|---|---|---|
| A ملف | متوسطة | منخفضة | ممتازة | لا | انتقالي/sandbox |
| B DPAPI | متوسطة–عالية | منخفضة–متوسطة | جيدة جداً | لا | KEK محلي (DR محسوب) |
| C KMS | عالية | متوسطة | متوسطة | نعم | حين توفّر سحابة |
| D Vault/HSM | عالية جداً | عالية | ممتازة | لا | نضج + مفاتيح تنظيمية |
| **E هجين** | قابلة للترقية | منخفضة→ | **ممتازة** | لا (حتى C) | **النشر الحالي** |
