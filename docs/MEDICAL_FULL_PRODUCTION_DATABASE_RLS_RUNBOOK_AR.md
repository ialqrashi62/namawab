# دليل صيانة قاعدة البيانات وأمان مستوى الصفوف (Database & RLS Runbook)
## نظام نما الطبي (NamaMedical) - وثيقة التسليم النهائي

يوثق هذا الدليل الهيكل الأمني لقاعدة بيانات الإنتاج الفعلي، وصلاحيات حساب التطبيق المحدود `nama_medical_app` وتأكيد سلامة فرض Row Level Security (RLS).

---

## 1. الهيكل الأمني لحسابات قاعدة البيانات (Database Roles)

* **المستخدم الإداري المالك للبيانات**: `postgres` (Superuser - يملك كامل الجداول والملفات ويقتصر استخدامه حصرياً على الصيانة الإدارية والنقل الهيكلي).
* **مستخدم اتصال التطبيق**: `nama_medical_app` (مستقل - ذو صلاحيات تشغيلية محدودة).
  - الصلاحيات: `CONNECT` على قاعدة البيانات، و `USAGE` على المخطط `public` وعمليات CRUD الحساسة على البيانات.
  - القيود: `NOSUPERUSER` (ليس مشرفاً)، و `NOBYPASSRLS` (لا يمكنه تجاوز RLS مطلقاً).

---

## 2. التحقق من فرض أمان مستوى الصفوف (RLS Enforcement)

تم تفعيل ميزة `FORCE ROW LEVEL SECURITY` على الجداول الـ 13 الحيوية لضمان عدم تسريب أي بيانات متقاطعة بين المنشآت الطبية المختلفة (المستأجرين).

* **أداة التحقق الهيكلي**:
  يتم التحقق من خلال تشغيل الاستعلام القياسي الموثق في [production_readiness_force_rls_validate.sql](docs/sql/production_readiness_force_rls_validate.sql) (مسار نسبي):
  ```bash
  sudo -u postgres psql -d nama_medical_web -f docs/sql/production_readiness_force_rls_validate.sql
  ```
* **المخرجات المطلوبة**:
  يجب أن تظهر كافة الجداول الـ 13 وتكون قيمة العمود `rls_enabled` مساوية لـ `t` (True) وقيمة العمود `rls_forced` مساوية لـ `t` (True).

---

## 3. التعامل مع مشكلات الصلاحيات وتغيير الهيكل (Database Operations)

* **تعديل الجداول (Schema Change/Alter)**: بما أن حساب التطبيق `nama_medical_app` مجرد من صلاحيات تعديل الجداول، فيجب إجراء أي تحديث هيكلي أو صيانة لقاعدة البيانات باستخدام مستخدم المالك `postgres` فقط.
* **سياسة إجازة الحساب**: يجب التأكد دائماً أن التطبيق لا يعمل بحساب `postgres` في ملف `.env` التشغيلي للإنتاج لمنع التفاف أو تجاوز سياسات عزل البيانات RLS.
* **فحص عزل المستأجرين**:
  في حال الشك بوجود تسريب في البيانات، يمكن اختبار العزل يدوياً عبر psql:
  ```sql
  BEGIN;
  SET ROLE nama_medical_app;
  -- تعيين سياق مستأجر وهمي
  SELECT set_config('app.tenant_id', '999', true);
  -- محاولة استعلام المرضى
  SELECT COUNT(*) FROM patients; -- يجب أن ترجع 0 سجلات لعدم تتبعها للمستأجر 999
  ROLLBACK;
  ```
