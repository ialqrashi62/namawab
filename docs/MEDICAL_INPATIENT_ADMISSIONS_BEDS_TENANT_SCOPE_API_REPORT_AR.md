# تقرير تطبيق عزل المستأجرين على مسارات التنويم الداخلي والأسرة (Inpatient Admissions & Beds Tenant Scope API Report)

وثيقة سرية لتوثيق إجراءات الحماية والخصوصية ومنع ثغرات IDOR وتكامل المستأجرين لنظام نما الطبي (NamaMedical).

---

## 1. الملخص التنفيذي (Executive Summary)

تم بنجاح إتمام مرحلة عزل مسارات التنويم الداخلي (Admissions) والأجنحة والغرف والأسرة (Wards & Beds) وحركات النقل الداخلي (Bed Transfers) في النظام الطبي لمنع تسريب بيانات المرضى المنومين وتداخل تخصيص الأسرة بين المستأجرين (SaaS Tenants) والفروع (Facilities).
لقد أثبتت الاختبارات الأمنية والمحاكاة نجاحاً كاملاً بنسبة 100% (53/53 اختباراً) دون إدخال أي تعديلات مدمرة على قاعدة البيانات أو تشغيل هجرات (Migrations)، ودون أي تداخل مع بيئة الإنتاج الفعلي.

---

## 2. نطاق المرحلة (Phase Scope)

اقتصر نطاق هذه المرحلة بدقة على تأمين وعزل مسارات التنويم والأسرة والغرف فقط:
* **إنشاء وعرض وتعديل التنويم** (Admission).
* **خروج المريض** (Discharge).
* **تسجيل وجلب جولات الطبيب اليومية** (Daily Rounds).
* **عرض الأجنحة والأسرة وإحصائيات إشغال الأسرة** (Wards, Beds, Bed Census).
* **نقل المرضى داخلياً بين الأسرة أو الغرف** (Bed Transfers).
* **التحقق من سياقات وملكية المرضى والأسرة والأجنحة** للمستأجر الحالي قبل أي عملية كتابة أو نقل لمنع ثغرات الـ IDOR.

### لماذا تم فصل التنويم والأسرة عن الطوارئ (Emergency)؟
* **طبيعة العمل**: حركات التنويم الداخلي هي حركات طويلة الأمد ومقترنة بحجز موارد حساسة (أجنحة وغرف وأسرة)، وتخضع لمنطق تنظيمي يختلف بالكامل عن تدفقات المرضى السريعة في قسم الطوارئ.
* **فصل المخاطر (De-risking)**: تقليل فرصة حدوث عطل في مسارات الطوارئ الحرجة أثناء تعديل وحجز الغرف والأسرة الخاصة بالتنويم العادي.
* **مستوى الحماية**: عزل الأسرة يمثل حاجة تنظيمية وأمنية لمنع تداخل حجز الأسرة الموزعة بين المستأجرين، في حين أن زيارات الطوارئ ترتبط مباشرة بمسارات الحوادث وعمليات المعاينة الفورية وسرعة الدخول، والتي سيتم تخصيص مرحلة مستقلة لها لاحقاً.

## 4. تفاصيل المسارات المؤمنة والاستعلامات (Secured Routes & SQL Queries)

تم تأمين نهايات المسارات الـ 10 التالية بفرض ميدل وير `requireTenantScope` وفلاتر العزل:

| اسم المسار (Route) | نوع العملية | الجداول المستخدمة | مستوى الخطر | فلتر المستأجر المطبق |
| :--- | :--- | :--- | :--- | :--- |
| `GET /api/wards` | قراءة | `wards` | P2 | `tenant_id = $1` |
| `GET /api/beds` | قراءة | `beds`, `wards` | P2 | `b.tenant_id = $2` والتحقق من جناح المستأجر |
| `GET /api/beds/census` | قراءة | `beds`, `wards`, `admissions` | P2 | `b.tenant_id = $1` و `a.tenant_id = $1` |
| `GET /api/admissions` | قراءة | `admissions` | P1 | `tenant_id = $1` (أو بالاشتراك مع الحالة) |
| `GET /api/admissions/:id` | قراءة تفصيلية | `admissions` | P1 | `WHERE id = $1 AND tenant_id = $2` (IDOR Prevention) |
| `POST /api/admissions` | إنشاء | `admissions`, `patients`, `beds` | P0 | ختم `tenant_id`/`facility_id` والتحقق من تبعية المريض والسرير |
| `PUT /api/admissions/:id/discharge` | تعديل | `admissions`, `beds`, `patients` | P0 | التحقق من ملكية التنويم أولاً، ثم التحديث بشرط `tenant_id` |
| `POST /api/admissions/:id/rounds` | إنشاء | `admission_daily_rounds`, `admissions`, `patients` | P1 | التحقق من التنويم والمريض، وختم `tenant_id`/`facility_id` |
| `GET /api/admissions/:id/rounds` | قراءة | `admission_daily_rounds`, `admissions` | P1 | التحقق من ملكية التنويم، وتصفية الجولات بـ `tenant_id` |
| `POST /api/bed-transfers` | إنشاء | `bed_transfers`, `admissions`, `patients`, `beds` | P0 | التحقق من التنويم والمريض والأسرة، وختم `tenant_id`/`branch_id` |

### الاستعلامات المؤجلة (Deferred Queries)
* **موظفو الأقسام والأطباء**: الاستعلامات على جدول `employees` أو `system_users` لا يتم فلترتها بـ `tenant_id` في هذه الأقسام كونها جداول حيوية تشغيلية عامة في بنية الخادم لبعض المهام المشتركة، وسيتم مراجعتها أمنياً عند هاردينغ مسارات الـ HR والصلاحيات بالكامل.

## 6. المخاطر المتبقية (Remaining Risks)

1. **قسم الطوارئ (Emergency Visits)**: ما زال قيد التطوير ولم يتم إخضاعه لعزل المستأجرين في هذه المرحلة، وهو ما يمثل خطورة تسريب في حال استدعاء نهايات مسارات الطوارئ مباشرة.
2. **العمليات الجراحية المفتوحة**: لا تزال بحاجة لمزيد من المتابعة لضمان التكامل التام بين حركات التنويم وحركات النقل لغرف العمليات دون تسريب.
3. **عدم تفعيل RLS (Row Level Security)**: العزل يتم حالياً برمجياً بالكامل في طبقة الـ Express API؛ وفي حال تمكن المهاجم من الوصول لقاعدة البيانات مباشرة، سيفتقد لعزل المستأجرين على مستوى الجداول لغياب RLS.
4. **تطابق الجداول المشتركة**: الجداول العامة كالأطباء والموظفين لم يطبق عليها عزل صارم بعد لتسهيل عمليات الترحيل والاختيار.
