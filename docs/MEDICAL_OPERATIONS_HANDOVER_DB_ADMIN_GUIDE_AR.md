# دليل إدارة قاعدة البيانات وإدارة سياسات RLS (Operations Handover DB Administration Guide)
## نظام نما الطبي (NamaMedical) - مرحلة التسليم والتشغيل للمالك

يوثق هذا المستند الدليل الإداري لقاعدة البيانات وصيانة وإدارة سياسات أمان مستوى الصفوف (Row Level Security - RLS) لمساعدة فرق العمليات على صيانة قاعدة البيانات بشكل آمن ومحمي.

---

### 1. إدارة قاعدة البيانات وسياق العمل (PostgreSQL Administration)

* **محرك قاعدة البيانات**: PostgreSQL 16 يعمل محلياً ويستمع على المنفذ `5432`.
* **محدودية الاتصال**:
  - الاتصال بقاعدة البيانات محصور محلياً على السيرفر (localhost) لمنع أي هجمات خارجية أو محاولات ربط بقاعدة البيانات من خارج السيرفر.
  - أي استعلام إداري يجب تشغيله عبر وسيط موثق وباستخدام المتغيرات البيئية المؤقتة.

---

### 2. تدقيق سياسات RLS النشطة (Active RLS Policies)

تم تفعيل وإنفاذ سياسات الـ RLS على 35 جدولاً لضمان العزل التام للمستأجرين وحماية البيانات السريرية والمالية. يتم التحقق من السياسات وقسريتها باستخدام الأمر التالي:
```sql
SELECT schemaname, tablename, policyname, cmd FROM pg_policies;
```

**أهم السياسات المطبقة**:
1. **المرضى (`patients`)**: `rls_patients_tenant_isolation`
2. **الفواتير (`invoices`)**: `rls_invoices_tenant_isolation`
3. **المواعيد (`appointments`)**: `rls_appointments_tenant_isolation`
4. **الوصفات والجرعات (`prescriptions`)**: `rls_prescriptions_tenant_isolation`
5. **الطوارئ والفرز (`emergency_visits`)**: `rls_emergency_visits_tenant_isolation`
6. **العمليات الجراحية (`surgeries`)**: `rls_surgeries_tenant_isolation`

---

### 3. صيانة الجداول وقوانين الإدارة (DB Maintenance Checklist)

- [ ] **التحقق الهيكلي الدوري**: تشغيل استعلام التحقق للتأكد من بقاء `rls_enabled` و `rls_forced` مفعلة للجداول الـ 13 الحساسة.
- [ ] **منع التعطيل العشوائي**: يُمنع منعاً باتاً تعطيل الـ RLS أو تشغيل `NO FORCE ROW LEVEL SECURITY` إلا في حالات الصيانة الطارئة الموثقة والمعتمدة.
- [ ] **صيانة الفهارس (Indexes)**: المحافظة على الفهارس المخصصة لـ `tenant_id` لضمان سرعة الاستجابة وكفاءة الاستعلامات.
