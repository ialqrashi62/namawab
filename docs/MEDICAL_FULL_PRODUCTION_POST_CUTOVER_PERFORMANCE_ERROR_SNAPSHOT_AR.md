## 1. مؤشرات استهلاك الموارد والأداء (Performance Metrics)

تم فحص التطبيق الإنتاجي المستضاف على السيرفر `204.168.144.74` ورصد مؤشرات الأداء الحالية:
* **حجم الذاكرة المستهلكة (PM2 Memory)**: `78.6 MB` (أداء ممتاز وضمن المعايير الآمنة لتطبيقات Node.js).
* **استهلاك المعالج (CPU)**: `0%` (الخادم مستقر وخفيف الاستهلاك).
* **عدد محاولات إعادة التشغيل (Restart Count)**: `11` محاولة (خلال 12 ساعة من التشغيل، وهي طبيعية وتخص عمليات إعادة التشغيل التشغيلية والتعديل ولا تمثل crash loop).
* **متوسط أوقات الاستجابة الخارجية (HTTPS Latency)**: ما بين `105ms` إلى `115ms` (ممتاز ومناسب لواجهات الاستخدام الطبي وتجربة الممارسين).

## 2. لقطة التحذيرات وسجلات الأخطاء المرصودة (Errors and Warnings Snapshot)

تم مراجعة سجلات أخطاء التطبيق وقت التشغيل وتصنيف التحذيرات المرصودة كالتالي:

### 2.1 تحذيرات تشغيلية حرجة (P1 Warnings)
* **غياب Redis**:
  `[SESSION INFO] No Redis configuration detected, using default MemoryStore for sessions.`
  * **السبب**: غياب متغيرات Redis في ملف بيئة الإنتاج `.env`.
* **تراجع الجلسات للميموري ستور**:
  `Warning: connect.session() MemoryStore is not designed for a production environment, as it will leak memory...`
  * **السبب**: التطبيق تراجع تلقائياً لاستخدام الذاكرة المحلية للجلسات بسبب غياب الاتصال بخادم Redis.

### 2.2 تحذيرات تشغيلية غير حرجة (P3 Warnings)
* **أخطاء هجرة waiting_queue**:
  `Migration error: relation "waiting_queue" does not exist`
  * **السبب**: سجل تاريخي ناتج عن محاولة تشغيل التطبيق واستدعاء تحديثات الجدول قبل إتمام بنائه في قاعدة البيانات. تم حل المشكلة تلقائياً وظهور الجدول وسجلاته بشكل سليم حالياً.
