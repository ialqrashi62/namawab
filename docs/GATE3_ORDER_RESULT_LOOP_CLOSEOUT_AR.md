# تقرير إغلاق Gate 3 — حلقة الأوامر↔النتائج + إقرار الطبيب بالنتائج
**التاريخ:** 2026-07-03  •  **الحالة:** ✅ ناجح  •  **Commit محلي:** namaweb `9589402` على `integration/all-epics` (لا push، لا DDL منفَّذ، لا نشر)

## المشكلة (من Gate 0)
- **لا يوجد `UPDATE orders` في النظام كله**: الأمر يبقى «pending» للأبد حتى بعد صدور النتيجة وتقريرها — قائمة عمل الطبيب لا تعكس الواقع.
- **لا إقرار من الطبيب المعالج** بالاطلاع على النتائج الحرجة/غير الطبيعية (الـcallback الموجود توثيق من جهة المختبر فقط، وفق CAP/Joint Commission، لكن حلقة الطبيب الآمر مفتوحة).

## ما نُفّذ (TDD: RED → GREEN)
1. **محرك نقي `result_loop.js`** (14 اختبارًا، fail-closed):
   - `shouldCloseLegacyOrder` — يسمح بإغلاق الأمر الأصلي فقط عند **تطابق المريض** بين العينة/الفحص والأمر وكون الأمر مفتوحًا؛ أي شك (مريض مفقود، أمر غير موجود، حالة غير معروفة) = رفض الإغلاق. إغلاق أمر المريض الخطأ = اختفاء عمل معلّق من قائمة العمل = خطر سلامة.
   - `ackRequirement` — سياسة الإقرار: حرج (`is_critical` أو HH/LL) = إقرار إلزامي؛ H/L = إلزامي بمستوى abnormal؛ علم غير معروف/مفقود = **إلزامي fail-closed** (نتيجة غير مصنّفة لا تتجاوز مراجعة الطبيب أبدًا).
2. **إغلاق الحلقة فعليًا**:
   - مختبر: `PUT /api/lab/results/:id/report` → يغلق `lab_radiology_orders` الأصلي (Completed + result_date) بعد نجاح الحارس، مع تدقيق «order closed (loop)».
   - أشعة: `PUT /api/radiology/reports/:id/sign` → نفس الإغلاق المحروس عبر `rad_exams.rad_order_id`.
   - **قرار مُتعمَّد**: جدول `orders` الموحّد (E-X) لا يُلمس — لا عينة تحمل معرّفه حتى يُفعَّل dispatch الخاص بـCPOE؛ التحديث الأعمى قد يغلق أمرًا خاطئًا (الازدواج المعرّفي قديم/موحّد موثّق في Gate 0).
3. **إقرار الطبيب (بنية جاهزة، تخزين بانتظار DDL)**:
   - `POST /api/results/:type(lab|rad)/:id/acknowledge` — المستوى من سياسة الخادم لا من العميل؛ منع التكرار عبر قيد فريد؛ يتطلب نتيجة verified (مختبر) أو تقرير Signed (أشعة).
   - `GET /api/results/unacknowledged` — قائمة عمل الطبيب للنتائج الموثّقة غير المُقرَّة (الحرِج أولًا؛ **علم NULL يُدرج** — fail-closed).
   - النقطتان تكتشفان وجود جدول `result_acknowledgements` عبر `to_regclass` وتعيدان **503 RESULT_ACK_PENDING_DDL** حتى اعتماد e49.
4. **Migration مرشّحة e49 (لم تُنفَّذ)**: جدول `result_acknowledgements` بـFORCE RLS وسياسة مستأجر وقيد فريد (tenant,type,result,clinician) + down/validate.
