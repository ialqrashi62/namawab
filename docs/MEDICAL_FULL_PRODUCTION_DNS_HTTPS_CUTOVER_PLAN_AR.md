# خطة العبور وتفعيل النطاق والتشفير (DNS and HTTPS Production Cutover Plan)
## نظام نما الطبي (NamaMedical) - مرحلة التخطيط للترقية والعبور للإنتاج

توثق هذه الخطة الخطوات الفنية والإجراءات الوقائية لتوجيه النطاق وتفعيل التشفير الآمن لنظام نما الطبي عند الانتقال للإنتاج الكامل دون إحداث أي تغيير أو تنفيذ فعلي حالياً.

---

### 1. معايير وإعدادات توجيه النطاق (DNS Cutover Settings)

1. **النطاق المستهدف (Domain Target)**:
   - النطاق الأساسي: `medical.nama.com.sa`
   - النطاق الفرعي للتوجيه: `www.medical.nama.com.sa`
2. **سجلات الـ DNS المطلوبة**:
   - سجل من النوع **A**: يربط النطاق الأساسي بالعنوان الرقمي الثابت لخادم الإنتاج (مثال: `A` -> `medical.nama.com.sa` -> `IP_PRODUCTION`).
   - سجل من النوع **CNAME**: يوجه الطلبات ببادئة www إلى النطاق الأساسي.
3. **استراتيجية عمر السجلات (TTL Strategy)**:
   - **قبل مرحلة العبور بـ 24-48 ساعة**: يتم خفض قيمة عمر السجل (TTL) في لوحة التحكم للـ DNS من القيمة الافتراضية (مثلاً 86400 ثانية / 24 ساعة) إلى قيمة منخفضة (مثل 300 ثانية / 5 دقائق) لتسريع انتشار التوجيه الجديد عند التحديث.
   - **خلال ساعة الصفر (Cutover)**: يتم تغيير السجل A للإشارة إلى خادم الإنتاج الفعلي.
   - **بعد استقرار العبور والتأكد من نجاح الانتقال بـ 24 ساعة**: يتم إعادة رفع قيمة عمر السجل (TTL) إلى القيمة الطبيعية (86400 ثانية) لتخفيف الحمل على خوادم الـ DNS.

---

### 2. خطة تفعيل شهادة الأمان وتجديدها (SSL Certificate Issuance & Renewal)

1. **استخراج شهادة SSL الإنتاجية**:
   - استخدام أداة Certbot الرسمية بالتكامل مع خادم Nginx لاستخراج شهادة مجانية وموثوقة من Let's Encrypt:
     ```bash
     # أمر افتراضي للاستخراج (للتخطيط فقط وليس للتنفيذ الفعلي حالياً)
     sudo certbot --nginx -d medical.nama.com.sa -d www.medical.nama.com.sa
     ```
   - نوع الفحص التلقائي المستخدم: تحدي منفذ الويب HTTP-01 (HTTP-01 Challenge).
2. **خطة التجديد التلقائي (Renewal Plan)**:
   - شهادات Let's Encrypt صالحة لمدة 90 يوماً.
   - تفعيل مؤقت تجديد تلقائي دوري يعمل مرتين يومياً عبر cron للتأكد من تجديد الشهادات قبل انتهائها بـ 30 يوماً:
     ```bash
     # أمر التحقق من التجديد (للتخطيط)
     sudo certbot renew --dry-run
     ```

### 3. إعدادات الحماية والتوجيه والملفات الآمنة (HTTPS redirection & Cookie Hardening)

1. **توجيه الـ HTTP إلى HTTPS بقوة**:
   - تهيئة خادم Nginx لإرجاع رمز التوجيه `301 Moved Permanently` لأي طلبات غير مشفرة واردة على منفذ `80`:
     ```nginx
     server {
         listen 80;
         server_name medical.nama.com.sa www.medical.nama.com.sa;
         return 301 https://$host$request_uri;
     }
     ```
2. **رأس الأمان والتحميل المسبق (HSTS Setup)**:
   - إضافة ترويسة الأمان HSTS لإخبار المتصفحات بعدم الاتصال بالتطبيق عبر HTTP نهائياً:
     ```nginx
     add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
     ```
3. **تحصين ملفات تعريف الارتباط للجلسات (Secure Cookies)**:
   - تهيئة وسيط جلسات Express لإنفاذ حقول الأمان لملفات الكوكيز لمنع قرصنتها:
     - `secure`: `true` (يمنع إرسال الكوكيز إلا عبر اتصال مشفر HTTPS).
     - `httpOnly`: `true` (يمنع قراءة الكوكيز عبر JavaScript بالموقع لحمايته من XSS).
     - `sameSite`: `'lax'` (يمنع إرسال الكوكيز في الطلبات العابرة للمواقع لحماية التطبيق من CSRF).

### 4. خطة التراجع السريع لنظام أسماء النطاقات (DNS Rollback Plan)

في حال فشل عملية العبور أو ظهور مشاكل غير قابلة للحل السريع أثناء مرحلة تفعيل الـ SSL/HTTPS:
1. **نقطة الاستعادة (Old Record)**: الحفاظ على سجلات الـ DNS القديمة التي تشير إلى خادم Staging الفعال والمستقر.
2. **توجيه التراجع**: تغيير سجل A فوراً في لوحة تحكم DNS للإشارة إلى عنوان IP الخاص بخادم Staging.
3. **وقت التعافي**: نظراً لخفض قيمة الـ TTL مسبقاً لـ 5 دقائق، سينتشر التراجع وسيستعيد المستخدمون إمكانية الوصول للبيئة السابقة خلال 5 دقائق كحد أقصى.
