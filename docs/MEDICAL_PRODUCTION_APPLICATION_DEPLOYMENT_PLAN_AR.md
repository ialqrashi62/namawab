# خطة نشر وتحديث كود خادم التطبيق (Production Application Deployment Plan)
## نظام نما الطبي (NamaMedical) - مرحلة التخطيط والتحقق

توثق هذه الوثيقة إجراءات بناء وتحديث ونشر الأكواد البرمجية لخادم الويب في بيئة الإنتاج الفعلي.

---

### 1. الاستعداد والتأهيل للنشر (Deployment Preparation)

* **نسخة الإطلاق المعتمدة (Release Candidate)**:
  * تحديد التاق أو الهاش الخاص بآخر commit مستقر ومجتاز للاختبارات (مثال: `626944f` أو أحدث).
* **خطوات البناء والتبعيات (Build Steps)**:
  1. جلب التحديثات من الفرع الرئيسي:
     `git pull origin master`
  2. تثبيت التبعيات الإنتاجية وتجميع ملفات التنسيق:
     `npm install --production`
     `npm run build:css`

---

### 2. تسلسل نشر وتفعيل الخدمة (Deployment Sequence)

1. **التحقق من متغيرات البيئة**:
   * التأكد من حقن `REDIS_HOST` وتحديث `SESSION_SECRET` و `NODE_ENV=production` في بيئة الخادم.
2. **إعادة تشغيل مدير العمليات (PM2 Restart)**:
   * تشغيل خادم الويب تحت إدارة PM2 وتمرير التحديثات بأقل زمن توقف:
     `pm2 restart nama-web --update-env`
3. **فحص الصحة المبدئي (Initial Health Check)**:
   * إرسال طلب فحص سريع لواجهة التحقق:
     `curl -I http://localhost:3000/api/health`
   * التأكد من استقبال الرمز `200 OK`.

---

### 3. خطة التراجع السريع للتطبيق (Application Rollback Path)

في حال فشل الخادم في العمل أو رصد أخطاء حرجة بعد النشر مباشرة:
1. العودة للنسخة السابقة الفعالة فوراً عبر Git:
   `git checkout <previous_stable_commit_hash>`
2. إعادة بناء التنسيقات وتحديث التبعيات:
   `npm install --production`
3. إعادة تشغيل الخادم في PM2 لاستعادة الخدمة السابقة:
   `pm2 restart nama-web --update-env`
* **معدل التوقف المتوقع**: أقل من **30 ثانية** أثناء التراجع.

---

### 4. الخلاصة وحالة العبور (Gate 6 Conclusion)

* **حالة بوابة تخطيط التطبيق**: **PASS** (تم توثيق وتخطيط إجراءات نشر التطبيق والتراجع بوضوح).
* **التوصية**: الانتقال للبوابة السابعة لتخطيط الشبكة وجدار الحماية DNS/SSL.

**القرار**: تم اجتياز البوابة بنجاح (**Gate 6: PASS**).
