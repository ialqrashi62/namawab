# تقرير تحصين حساب اتصال قاعدة البيانات (App DB User Hardening Report)
## نظام نما الطبي (NamaMedical) - مرحلة حل حاصرات الإنتاج الفعلي

يوثق هذا التقرير خطوات ونتائج تنفيذ إنشاء وضبط مستخدم قاعدة بيانات ذي صلاحيات محدودة لتشغيل تطبيق الويب لتجنب استخدام حساب مالك الجداول `postgres` والالتفاف حول Row Level Security (RLS).

---

## 1. الإجراءات المنفذة لتقليل الصلاحيات (Actions Taken)

تم إنجاز الخطوات التالية لترسيخ مبدأ الحد الأدنى من الصلاحيات (Least Privilege):
1. **إنشاء الحساب المحدود**: تم بنجاح إنشاء حساب الاتصال `nama_medical_app` على مستوى PostgreSQL.
2. **سحب الصلاحيات الإدارية**: تم تأكيد حظر أي صلاحيات إدارية عليا أو القدرة على تجاوز سياسات عزل البيانات:
   - `NOSUPERUSER`: الحساب ليس مشرفاً عاماً.
   - `NOBYPASSRLS`: الحساب خاضع بالكامل وبلا استثناء لسياسات Row Level Security.
3. **منح صلاحيات التشغيل فقط**:
   - منحه صلاحية الاتصال (`CONNECT`) بقاعدة بيانات الإنتاج `nama_medical_web`.
   - منحه صلاحية استخدام المخطط العام (`USAGE ON SCHEMA public`).
   - منحه صلاحيات البيانات الأساسية فقط (`SELECT, INSERT, UPDATE, DELETE`) على كافة الجداول الحالية في المخطط العام `public`.
   - منحه صلاحية استخدام المتسلسلات (`USAGE, SELECT`) لتوليد المعرفات التلقائية للمفاتيح الأساسية.
4. **تأمين الجداول المستقبلية**: تم ضبط الصلاحيات التلقائية لقاعدة البيانات (`ALTER DEFAULT PRIVILEGES`) لضمان تطبيق نفس القيود والصلاحيات المحدودة على أي جداول أو متسلسلات يتم إنشهاؤها لاحقاً.
5. **تحديث ملفات البيئة**: تم تحديث ملف الإعدادات البيئية الفعلي `.env` على خادم الإنتاج لاستخدام الحساب الجديد `nama_medical_app` بدلاً من حساب المالك `postgres`.

---

## 2. مصفوفة الصلاحيات المعتمدة للحساب الجديد

| نوع الصلاحية / القيود | الحالة | الأثر الأمني |
| :--- | :---: | :--- |
| صلاحية الاتصال بقاعدة البيانات | **نشط (ACTIVE)** | الاتصال بـ `nama_medical_web` فقط. |
| صلاحية Superuser | **معطل (DISABLED)** | لا يمكن للمستخدم مسح المخطط أو إيقاف السيرفر. |
| صلاحية تجاوز RLS (Bypass RLS) | **معطل (DISABLED)** | خاضع إجبارياً لعزل البيانات والمستأجرين. |
| عمليات البيانات (CRUD) | **مسموح (ALLOWED)** | قراءة وكتابة وتحديث وحذف السجلات التطبيقية. |
| عمليات الهيكلة (DDL/Alter) | **ممنوع (FORBIDDEN)** | الحساب لا يملك جداول ولا يمكنه تعديل هيكل قاعدة البيانات. |

---

## 3. التحقق الأمني من الالتزام بالمعايير

* **سرية البيانات**: لم يتم طباعة أو تضمين كلمة مرور الحساب الجديد في التقارير أو كود السورس.
* **عزل المالك**: تم تحويل التطبيق بالكامل للاتصال بالبيانات دون امتلاك الجداول، مما يعطل تلقائياً خاصية تجاوز RLS المتاحة للـ Table Owner.
* **الحالة التشغيلية**: **`PASS`**
