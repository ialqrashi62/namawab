### 4. سياسة Redis في الإنتاج (Production Redis Policy)

* **إلزامية Redis في الإنتاج**: يعتبر خادم Redis إلزامياً بالكامل لإدارة متجر الجلسات في بيئة الإنتاج الفعلي.
* **حظر MemoryStore**: يمنع منعاً باتاً تشغيل النظام إنتاجياً باستخدام `MemoryStore` كوضع تشغيل عادي أو fallback مقبول في الإنتاج. التراجع للميموري ستور مقبول فقط في بيئات التطوير والـ Staging/Rehearsal أو كحالة تطوير غير إنتاجية.
* **شروط التشغيل والتراجع**:
  - إذا فشل Redis قبل النشر: يتم إلغاء النشر فوراً وتثبيت القرار كـ `NO_GO_STOP`.
  - إذا فشل Redis بعد أو أثناء النشر: يتم تفعيل سياسة إيقاف خط الإنتاج فوراً (STOP_THE_LINE) ثم تشغيل التراجع التلقائي (ROLLBACK) للالتزام المستقر السابق، أو تفعيل خطة الطوارئ (Incident Plan).
  - لا يوجد fallback صامت في بيئة الإنتاج الفعلي.
  - لا يُصنف النظام كجاهز للإنتاج (`Production-ready`) إذا كان متجر الجلسات يعمل على `MemoryStore`.

**الحقول المعيارية المعتمدة لسياسة الإنتاج**:
```yaml
REDIS_REQUIRED_FOR_PRODUCTION: YES
MEMORYSTORE_ALLOWED_FOR_PRODUCTION: NO
REDIS_FAILURE_BEFORE_DEPLOY: NO_GO_STOP
REDIS_FAILURE_AFTER_DEPLOY: STOP_THE_LINE_ROLLBACK
```
