# دليل تشغيل خادم الويب وصيانة خادم التطبيقات (Operations Handover Server Runbook)
## نظام نما الطبي (NamaMedical) - مرحلة التسليم والتشغيل للمالك

يوثق هذا المستند دليل تشغيل وصيانة خادم التطبيق (Node.js/Express) المدار تحت مدير العمليات PM2 لضمان استقرار الخادم وحل مشاكله التشغيلية اليومية.

---

### 1. إدارة عملية التطبيق تحت PM2 (Process Management)

* **اسم العملية المعتمد**: `nama-web`
* **مسار ملف الخادم الرئيسي**: مجلد التطبيق المخصص `namaweb/` وملف `server.js`.
* **مسارات سجلات الخادم**:
  - سجل المخرجات: `%USERPROFILE%\.pm2\logs\nama-web-out.log`
  - سجل الأخطاء: `%USERPROFILE%\.pm2\logs\nama-web-error.log`

---

### 2. الأوامر التشغيلية الأساسية (Operational Commands)

#### أ. إعادة التشغيل وإنعاش الخدمة (PM2 Restart)
لإعادة تشغيل خادم الويب وتطبيق أي تعديلات أو متغيرات بيئية جديدة:
```bash
pm2 restart nama-web --update-env
```

#### ب. مراقبة سجلات التشغيل الحية (PM2 Logs)
لمراقبة سجلات التشغيل وأخطاء الاتصال بـ Redis أو قاعدة البيانات:
```bash
pm2 logs nama-web --lines 100
```

#### ج. عرض مؤشرات الأداء الحالية (PM2 Show)
لعرض استهلاك المعالج والذاكرة وتأخير حلقة الأحداث:
```bash
pm2 show nama-web
```

---

### 3. إرشادات حل المشكلات والصيانة (Troubleshooting)

1. **حالة تعذر الاتصال بـ Redis**:
   - **المؤشر**: رصد رسالة تحذير في سجلات PM2 تفيد بفشل الاتصال والتراجع الصامت للميموري ستور.
   - **الإجراء**: التحقق من تشغيل حاوية Redis في Docker ومطابقة المنفذ `6379`.
2. **استهلاك موارد مرتفع**:
   - **المؤشر**: تجاوز الذاكرة العشوائية لـ `500 MiB` أو استهلاك المعالج لـ `80%`.
   - **الإجراء**: تشغيل أخذ عينة كومة الذاكرة عبر PM2 `pm2 trigger nama-web km:heapdump` وتحليلها.
