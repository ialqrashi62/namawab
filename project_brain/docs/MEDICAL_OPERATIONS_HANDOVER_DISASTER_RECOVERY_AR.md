# خطة الاستعادة والتعافي من الكوارث (Operations Handover Disaster Recovery Plan)
## نظام نما الطبي (NamaMedical) - مرحلة التسليم والتشغيل للمالك

يوثق هذا المستند خطة التعافي من الكوارث (Disaster Recovery Plan) وإجراءات استعادة قاعدة البيانات وتفعيل التراجع الهيكلي والبرمجي السريع لضمان سلامة العمليات الطبية في حالات الطوارئ P0.

---

### 1. إجراء استعادة قاعدة البيانات (Database Restore Procedure)

عند رصد أي تلف في هيكل الجداول أو فقدان للبيانات، يتم استعادة قاعدة البيانات لآخر نسخة احتياطية آمنة وموثقة (مثل النسخة الاحتياطية المأخوذة قبل الترقية):

1. **إيقاف خادم الويب مؤقتاً**:
   `pm2 stop nama-web`
2. **تشغيل أمر الاستعادة الفعلي (مع تعويض مسار ملف الاستعادة)**:
   ```bash
   pg_restore -h localhost -p 5432 -U postgres -d nama_medical_web -c -v <backup_file_path>
   ```
3. **تشغيل التحقق الهيكلي**:
   التأكد من اكتمال استعادة الجداول الـ 148 ونجاح الفرض عبر استعلامات التحقق المعتمدة.
4. **إعادة تشغيل خادم الويب**:
   `pm2 start nama-web`

---

### 2. خطة التراجع السريع لـ RLS (RLS Rollback Plan)

في حال رصد أي مشكلة أداء أو تعارض وظيفي بسبب فرض سياسات RLS، يتم إيقاف وتجميد قسريتها على الفور كالتالي:
1. **تجميد السياسات**: تشغيل السكربت المعتمد لإلغاء القسرية:
   ```bash
   psql -h localhost -p 5432 -U postgres -d nama_medical_web -f docs/sql/production_readiness_force_rls_down.sql
   ```
2. **التحقق من حالة قاعدة البيانات**: التأكد من تحول الجداول للحالة `rls_forced = f`.

---

### 3. خطة التراجع البرمجي السريع (Application Rollback)

إذا تطلب الأمر التراجع البرمجي الكامل للإصدار المستقر السابق:
1. **التراجع عن كود التطبيق**:
   ```bash
   git checkout fe2f58a20960e69697b3413e8b8dad5a9c9e3c62
   git submodule update --init --recursive
   ```
2. **إعادة التثبيت والتشغيل**:
   - الدخول لمجلد التطبيق وتشغيل `npm install --production && npm run build:css`.
   - إعادة تشغيل التطبيق تحت PM2 مع إنفاذ المتغيرات.
