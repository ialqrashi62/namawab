# دليل إجراءات استعادة وتدوير حساب المدير العام في بيئة Staging
## نظام نما الطبي (NamaMedical)

يوفر هذا المستند دليلاً تشغيلياً معتمداً لمديري الأنظمة لاستعادة الوصول وحل مشكلة فقدان كلمة مرور حساب المدير العام `admin` في بيئة Staging بأمان تامة وبشكل يتوافق مع الضوابط الأمنية.

---

### 1. شروط وضوابط الاستخدام والصلاحية (Scope & Authorization)

* **متى يُستخدم الإجراء**: عند فقدان كلمة المرور الخاصة بحساب `admin` أو الرغبة في تدوير الاعتمادات الأمنية للاشتباه في حدوث تسريب.
* **من يملك صلاحية التنفيذ**: يقتصر تنفيذ هذا الإجراء حصراً على مسؤولي خوادم Staging المخولين بالولوج المباشر عبر بروتوكول SSH (مالكو مفتاح الولوج الخاص).
* **تحذير هام**: يُمنع استخدام هذا الإجراء أو السكربتات المرفقة في بيئة الإنتاج الفعلي (Production) حيث يجب أن تخضع بيئة الإنتاج لآلية تدوير مفاتيح واعتمادات مشددة ومنفصلة تماماً ومراقبة بشكل كامل.

---

### 2. خطوات التنفيذ الآمنة (Execution Steps)

لتنفيذ التدوير بأمان وبدون كشف أي أسرار في شاشات الإدخال أو مستودعات الكود، يتم اتباع الخطوات التالية:

#### أولاً: توليد كلمة مرور قوية
يتم توليد كلمة المرور الصريحة باستخدام أداة آمنة (مثل `openssl rand` أو وحدة `secrets` في بايثون)، على أن تكون بطول لا يقل عن 16 رمزاً وتحتوي على حروف كبيرة وصغيرة وأرقام ورموز خاصة.

#### ثانياً: حساب الهاش وتحديث قاعدة البيانات
1. يتم حساب هاش bcrypt (بقيمة Cost تساوي 12) محلياً على جهاز التطوير أو الخادم.
2. يتم تحديث جدول `system_users` في قاعدة البيانات باستخدام استعلام SQL موجه عبر قناة الاستلام القياسية (stdin) لـ `psql` لتجنب حفظ الاستعلام في سجل الأوامر التاريخية (bash history):
   ```bash
   sudo -u postgres psql -d nama_medical_web
   ```
   ثم كتابة استعلام التحديث وتطبيق الهاش مباشرة.

#### ثالثاً: تسليم كلمة المرور بشكل آمن وخارج Git
1. يتم حفظ كلمة المرور الصريحة المحدثة في ملف مؤقت معزول على الخادم في المسار `/root/admin_password.txt`.
2. يتم تعديل صلاحيات الملف فوراً ليصبح مقروءاً ومكتوباً فقط للمستخدم root:
   ```bash
   chmod 600 /root/admin_password.txt
   ```
3. يقوم المشرف بنسخ كلمة المرور من الملف وحفظها في مدير كلمات مرور المنشأة (Password Manager) الآمن والمشفر.
4. يتم تسليم الحساب للإداريين المعنيين خارج قنوات الاتصال العامة والمفتوحة.

#### رابعاً: تنظيف السيرفر والسجلات
1. يتم حذف ملف كلمة المرور الصريحة `/root/admin_password.txt` فور تأكيد الحفظ والاستلام الآمن.
2. يتم فحص سجلات أحداث PM2 وسجلات Nginx للتأكد التام من خلوها من أي إشارة لكلمة المرور أو الهاش:
   ```bash
   pm2 logs --lines 100 --nostream
   ```
3. يتم تنظيف سجل الأوامر في الخادم للتخلص من أي آثار للاستعلامات المباشرة:
   ```bash
   history -c
   ```

---

### 3. خطة التراجع في حال الفشل (Rollback Plan)

في حال فشل عملية التحديث أو حدوث انقطاع أدى لعطل في قاعدة البيانات:
1. يتم استعادة النسخة الاحتياطية الأخيرة لقاعدة البيانات Staging المأخوذة فوراً قبل البدء بالإجراء.
2. يتم إعادة تشغيل خادم التطبيق عبر PM2 للتحقق من رجوع الحالة المستقرة السابقة:
   ```bash
   pm2 restart nama-medical-erp
   ```
3. فحص سجلات الأخطاء في Nginx للتحقق من تلاشي أي انقطاعات.
