### 2. تسلسل وخطوات البناء والنشر (Deployment & Build Steps)

يتم تنفيذ عملية النشر بالترتيب الصارم والتسلسل التالي:
1. **تحديث السورس كود (Fetch Code)**:
   - سحب الالتزام المعتمد من المستودع وتأكيد مطابقة الهاشات الرقمية.
2. **تهيئة المتغيرات البيئية (Setup Environment)**:
   - حقن ملف التكوين `.env` للإنتاج وتثبيت اتصالات Redis وقاعدة البيانات والرموز السرية.
3. **تثبيت التبعيات البرمجية (Install Dependencies)**:
   - تشغيل التثبيت النظيف للتبعيات استناداً لملف القفل لضمان عدم ترقية أي مكتبة خارج السيطرة:
     ```bash
     npm ci --only=production
     ```
4. **بناء وتجميع أنماط التنسيق (CSS Build)**:
   - تجميع ملفات الأنماط لترقية واجهة المستخدم المتميزة ودعم الـ RTL:
     ```bash
     npm run build:css
     ```
5. **تنفيذ هجرات قاعدة البيانات (Database Migrations)**:
   - تشغيل هجرات الـ RLS والسياسات المعتمدة تحت كتل المعاملات الآمنة.
6. **تشغيل وإدارة الخدمة (PM2 Startup)**:
   - بدء تشغيل الخدمة تحت إدارة PM2 بالاسم الإنتاجي المعتمد لضمان إعادة التشغيل التلقائي عند انقطاع الموارد:
     ```bash
     npx pm2 start server.js --name "nama-web-prod"
     ```

### 3. فحوصات الصحة والقبول الميداني (Health & Smoke Tests)

فور تشغيل الخدمة، يجب إجراء الفحوصات التالية فوراً للقراءة فقط:
1. **فحص نقطة الاستدلال الصحي (Health Endpoint Check)**:
   - إرسال طلب استعلام للمسار `/api/health` والتأكد من إرجاع رمز الاستجابة `200 OK` والحالة التشغيلية `UP`.
2. **اختبار الدخان للقبول (Smoke Acceptance)**:
   - اختبار تسجيل الدخول الخاطئ وتأكيد حظره (401 Unauthorized).
   - اختبار تسجيل الدخول الإداري الصحيح ومطابقة التوجيه بنجاح.
   - التحقق من تصفية هويات المستأجرين للوحة التحكم الرئيسية وعيادة الطبيب والتمريض.
   - مطابقة عمل محدد الطلبات (Rate Limiting) وحظر المحاولات المتكررة (HTTP 429).

1. **الالتزام المعتمد للتراجع (Rollback Commit Hash)**:

2. **خطوات التراجع الميداني**:
   - إيقاف خدمة PM2 الحالية:
     ```bash
     npx pm2 stop "nama-web-prod"
     ```

     ```bash
     git checkout <LAST_STABLE_COMMIT_HASH>
     ```

   - استعادة قاعدة البيانات من النسخة الاحتياطية المأخوذة قبل الترقية إذا لزم الأمر.
