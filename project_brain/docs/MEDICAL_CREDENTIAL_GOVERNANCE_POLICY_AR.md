# سياسة حوكمة بيانات المصادقة وبيانات الدخول
## نظام نما الطبي (NamaMedical)

تحدد هذه السياسة الضوابط والقواعد الأمنية الملزمة لإدارة بيانات الدخول وكلمات المرور الخاصة بنظام نما الطبي لضمان سرية البيانات وسلامة البيئات التشغيلية.

---

### 1. القواعد العامة لحماية كلمات المرور (Password Security Principles)

1. **حظر تخزين كلمات المرور الصريحة**: يمنع منعاً باتاً تخزين أو كتابة كلمات مرور صريحة (Plaintext) في أي ملفات تابعة للمستودع البرمجي، أو في سجلات قواعد البيانات، أو وثائق التقارير.
2. **التشفير القوي (Strong Hashing)**: يجب تشفير جميع كلمات المرور باستخدام خوارزميات التجزئة الآمنة (مثل bcrypt بـ Cost لا يقل عن 12).
3. **منع الأسرار في المستودع البرمجي**: يحظر تماماً رفع أو إدراج أي عناوين قواعد بيانات (DATABASE_URL)، أو كلمات مرور، أو مفاتيح تشفير، أو ملفات بيئية (`.env`) داخل مستودعات Git. يتم استخدام ملفات التهيئة المحصنة والمتغيرات البيئية للخادم بدلاً من ذلك.
4. **عزل كامل للبيئات (Environment Separation)**: يحظر استخدام كلمات مرور أو مفاتيح تشفير متطابقة أو متشابهة بين بيئة Staging وبيئة الإنتاج (Production). لكل بيئة اعتماداتها المستقلة تماماً.

---

### 2. إدارة حسابات الإدارة والموظفين (Account Governance)

1. **حظر الحسابات المشتركة**: يمنع مشاركة حساب المدير العام `admin` بين أكثر من موظف. يجب تخصيص حساب إداري مستقل لكل فرد من طاقم تقنية المعلومات والمشرفين لمتابعة المسؤولية القانونية وفحص سجل الأحداث.
2. **تدوير كلمات المرور (Password Rotation)**: يجب تغيير وتدوير كلمات مرور الحسابات الحساسة دورياً (كل 90 يوماً على الأكثر)، وفوراً بعد أي إجراء إعادة تعيين (Reset) أو اشتباه في تسريب البيانات.
3. **إلغاء الوصول الفوري (Access Revocation)**: يجب تعطيل حسابات الموظفين والمديرين والتقنيين السابقين فور انتهاء علاقتهم بالمنشأة، مع مراجعة صلاحيات الوصول والربط مع الأجهزة بشكل دوري (كل شهر).

---

### 3. التوصيات والتحسينات المستقبلية (Future Roadmap)

1. **إضافة سجل تدقيق لتعديل كلمات المرور (Credential Audit Log)**: تسجيل أي عملية تغيير لكلمة المرور أو تحديث للصلاحيات في جدول مستقل `audit_trail` مع تدوين هوية المنفذ وعنوان الآي بي ووقت العملية.
2. **تطبيق المصادقة الثنائية (MFA)**: فرض التحقق الإضافي لجميع الحسابات الإدارية وحسابات الأطباء لتجنب مخاطر سرقة الحسابات عبر تقنيات الهندسة الاجتماعية.
3. **الربط مع الدليل النشط (LDAP/AD)**: التوصية بربط النظام مستقبلاً مع نظام إدارة الهويات الموحد للمنشأة لتبسيط سحب الصلاحيات وإدارة الهويات مركزياً.
