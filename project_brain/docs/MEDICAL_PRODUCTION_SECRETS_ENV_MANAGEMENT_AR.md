# تصميم إدارة الأسرار والمتغيرات البيئية (Secrets & Environment Management Design)
## نظام نما الطبي (NamaMedical) - خطة الجاهزية للإنتاج

يوثق هذا التصميم سياسات وممارسات حماية البيانات السرية، كلمات المرور، رموز الوصول (API Tokens)، واعتمادات البيئة البرمجية من التسريب أو سوء الاستخدام، مع وضع آليات تدوير دورية وآمنة لها.

---

## 1. قواعد أمن وحوكمة المستودع (Git Exclusions & Hygiene)

### 1.1 منع تتبع ملفات البيئة النشطة
* يمنع منعاً باتاً تحت أي ظرف رفع أو تتبع ملفات التكوين البيئي التي تحتوي على قيم فعلية (مثل `.env` أو `.env.production`) داخل مستودع Git العام أو الخاص.
* يلتزم المطورون فقط بتزويد نموذج تكوين فارغ باسم `.env.example` يوضح هيكل البيانات المطلوبة دون احتوائها على قيم حقيقية.

### 1.2 فحص الأسرار التلقائي (Secret Scanning Gate)
* تم دمج قواعد فحص صارمة لمنع إدخال الأسرار في المستودع:
  * يتم تشغيل أدوات مسح الأسرار (مثل `gitleaks` أو `git-secrets`) كجزء من خطوط أتمتة البناء والتحقق (CI/CD) للتحقق من عدم وجود أي كلمات مرور أو مفاتيح تشفير مكشوفة في التعديلات الجديدة قبل دمجها.

---

## 2. معالجة وحماية اعتمادات قاعدة البيانات (DATABASE_URL & PostgreSQL Credentials)

لتفادي كتابة كلمات المرور صراحة في ملفات الكود أو سجلات التشغيل:

* **متغير الاتصال بـ PostgreSQL (`DATABASE_URL`)**:
  * يتم تمرير المتغير فقط عبر البيئة التشغيلية للخادم أو سحابة التشغيل (Environment Variables).
  * لا يتم كتابة السلسلة التي تحتوي على كلمة المرور في أي كود مصدري أو مستند تشغيلي.
* **استخدام `PGPASSWORD` في أدوات CLI**:
  * عند تشغيل أوامر قاعدة البيانات في أدلة التشغيل (مثل `pg_dump` أو `psql`)، يتم تمرير كلمة المرور مؤقتاً عبر المتغير البيئي `PGPASSWORD` أو عبر ملف `.pgpass` الخاص بالنظام مع تحديد صلاحياته بـ `600` (الوصول لمدير النظام فقط)، ويُمنع كتابتها بشكل صلب في نصوص الأوامر.
  * يتم تنظيف المتغير بعد انتهاء الأمر مباشرة.

---

## 3. حماية أسرار الخادم والخدمات المدمجة (Server Secrets & API Keys)

يتم تنظيم أسرار خادم Express.js والخدمات الخارجية كما يلي:

| السر التشغيلي | الغرض | طريقة التخزين الآمنة | سياسة التدوير (Rotation Policy) |
| :--- | :--- | :--- | :--- |
| **SESSION_SECRET** | توقيع وتأمين كوكيز جلسات المرضى | قيمة عشوائية بطول 64 حرفاً في البيئة | كل 90 يوماً أو عند تغيير المفاتيح |
| **REDIS_PASSWORD** | الاتصال بمتجر الجلسات الموزع Redis | مشفر في تكوين الخدمة محلياً | عند تحديث الشبكة أو فترات الصيانة |
| **JWT_SECRET** | توقيع وتفويض رموز الدخول للمستأجرين | مفتاح مشفر يتم قراءته ديناميكياً | كل 6 أشهر |
| **EMAIL_SMS_CREDENTIALS** | إرسال تنبيهات المواعيد وتنبيهات الأمان | مشفرة عبر مدير أسرار مركزي | سنوياً |
| **DEPLOYMENT_SSH_KEYS** | مفاتيح النشر الآمن والاتصال بالخادم | SSH Keys محمية بكلمة مرور على خادم CI | كل 180 يوماً |

---

## 4. تطبيق مبدأ الصلاحيات الأدنى لقاعدة البيانات (Least Privilege Model)

لتأمين عزل المستأجرين وقاعدة البيانات:
1. **فصل المستخدمين**: لا يقوم خادم الويب (Express) بالاتصال بقاعدة البيانات باستخدام حساب مالك النظام الخارق (`postgres`) في الإنتاج.
2. **إنشاء حساب تطبيق محدود**: يتم إنشاء حساب مخصص للتطبيق (`nama_app_user`) يمتلك فقط صلاحيات `SELECT`, `INSERT`, `UPDATE`, `DELETE` على جداول التطبيق، وتُسحب منه صلاحيات `DDL` أو تعديل المخطط (`ALTER TABLE` / `DROP TABLE`).
3. **تفعيل الـ RLS للحساب المحدود**: تضمن سياسات RLS إنفاذ شروط العزل على مستخدم التطبيق المحدود بشكل صارم وتلقائي.

---

## 5. قائمة فحص البيئة للإنتاج (Production Environment Checklist)

قبل بدء تشغيل النظام في الإنتاج، يجب التأكد من ضبط المتغيرات التالية بدقة خارج المستودع:

- [ ] **NODE_ENV**: مضبوط على القيمة `production` لتفعيل تحسينات الأمان وضغط الملفات وإيقاف إظهار تفاصيل الخطأ (Stack Traces) للعملاء.
- [ ] **PORT**: رقم المنفذ الآمن الذي يستمع عليه الخادم خلف Nginx (مثل `3000` محلياً).
- [ ] **SESSION_SECRET**: تم توليد مفتاح جديد قوي وفريد وخاص ببيئة الإنتاج.
- [ ] **DATABASE_URL**: يشير لقاعدة البيانات الإنتاجية المؤمنة المعزولة باستخدام بروتوكول SSL (`sslmode=require`).
- [ ] **REDIS_URL**: يشير لخادم Redis المؤمن الخاص بالجلسات الموزعة مع التوثيق بكلمة مرور قوية.
- [ ] **ADMIN_INITIAL_PASSWORD_HASH**: هاش مسبق لمدير النظام الافتراضي، تم كتابته في قاعدة البيانات لتجنب استخدام كلمات مرور افتراضية مكشوفة.
- [ ] **TRUST_PROXY**: مضبوط على `true` لأن خادم Express يعمل خلف Nginx Proxy لضمان استقبال الـ IP الحقيقي للعميل بنجاح للحد من محاولات الاختراق وRate Limiting.
