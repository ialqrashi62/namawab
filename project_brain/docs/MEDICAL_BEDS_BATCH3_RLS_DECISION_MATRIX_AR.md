# مصفوفة قرارات سياسات الحماية RLS - الدفعة الثالثة (Batch 3 RLS Decision Matrix)
## نظام نما الطبي (NamaMedical) - بيئة Staging

يوثق هذا التقرير مصفوفة القرارات الخاصة بتفعيل سياسات الحماية على مستوى الصف (RLS Decision Matrix) للعمليات والكيانات المرتبطة بالخروج والإشغال والإحصاء الطبي.

---

### 1. مصفوفة الكيانات والجداول المستهدفة (Table Decision Matrix)

بما أن عمليتي الخروج والإشغال لا تعتمدان على جداول مخصصة جديدة بل تستعمل الجداول الحالية، يوضح الجدول التالي قرار الحماية لكل كيان:

| الكيان / الجدول (Table/Entity) | حالة RLS الحالية | القرار الفني المعتمد (Decision) | التوصيف الفني |
| :--- | :--- | :---: | :--- |
| **حركات التنويم (`admissions`)** | مفعّل (Batch 2) | **ALREADY_ENABLED** | العمليات التحديثية للخروج (Discharge Update) تخضع تلقائياً لـ RLS. |
| **الأسرة والملكية (`beds`)** | مفعّل (Batch 1) | **ALREADY_ENABLED** | عمليات إخلاء أو شغل السرير عند الخروج والقبول تخضع تلقائياً لـ RLS. |
| **سجل المرضى (`patients`)** | مفعّل (Foundation) | **ALREADY_ENABLED** | تحديث حالة المريض تخضع لسياسات عزل هويات المرضى. |
| **الأجنحة الطبية (`wards`)** | مفعّل (Batch 1) | **ALREADY_ENABLED** | قراءة الأجنحة ضمن سياق المستأجر مؤمنة بالكامل. |
| **التحويلات الداخيلة (`bed_transfers`)** | مفعّل (Batch 2) | **ALREADY_ENABLED** | أي حركة نقل أو تعديل معزولة تماماً. |
| **الجولات السريرية اليومية (`admission_daily_rounds`)**| غير مفعّل | **DEFER_TO_BATCH4** | يتم تأجيل عزل جدول الجولات الطبية للدفعة الرابعة لعدم ارتباطه المباشر بالإشغال. |

---

### 2. مصفوفة حوكمة مسارات العمليات التشغيلية (Operational Workflows Matrix)

| العملية التشغيلية (Workflow) | الجداول المشاركة | القرار الأمني (Security Decision) | آلية الحماية |
| :--- | :--- | :---: | :--- |
| **تسجيل الخروج الطبي (Discharge)** | `admissions`, `beds`, `patients` | **ALREADY_ENABLED** | تتم العمليات بالتحديث المباشر المعزول عبر معرف المستأجر من الجلسة. |
| **حساب الإشغال الحالي (Occupancy)** | `beds`, `wards`, `admissions` | **API_ONLY_DERIVED** | استعلام ديناميكي مدمج يعتمد على الجداول المعزولة بـ RLS تلقائياً. |
| **إحصاء الأسرة اليومي (Census)** | `beds`, `wards` | **API_ONLY_DERIVED** | تصفية تلقائية لقدرة المنشأة الاستيعابية على مستوى قاعدة البيانات. |
| **إلغاء الخروج (Discharge Reversal)** | `admissions`, `beds`, `patients` | **ALREADY_ENABLED** | يتم التحقق من توفر السرير وتحديث الحالة تحت سياق نفس المستأجر. |

---

### 3. تقييم المخاطر وقرار التطبيق (Risk Evaluation & Application Decision)

1. **هل يلزم تشغيل هجرة قاعدة بيانات (Migration Run)؟**
   * **القرار:** `NO`. جميع الجداول المعنية مؤمنة بـ RLS وجاهزة للخدمة.
2. **هل يوجد خطر خرق عزل المستأجرين (Cross-Tenant Leak Risk)؟**
   * **القرار:** `LOW/SECURED`. تمنع سياسات RLS الحالية أي مستأجر من تحديث بيانات مستأجر آخر أو شغل أسرته الشاغرة.
3. **قرار المتابعة:** الانتقال لمرحلة مراجعة أمان النهايات البرمجية (API Security Review).
