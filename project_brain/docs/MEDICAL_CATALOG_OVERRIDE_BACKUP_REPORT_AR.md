# تقرير النسخ الاحتياطي قبل تطبيق الكتالوج (Backup Report)
## نظام نما الطبي (NamaMedical) - بيئة Staging

يوثق هذا التقرير عملية النسخ الاحتياطي لقاعدة بيانات Staging التي تم إجراؤها بنجاح قبل تطبيق تعديلات المخطط وأي DDL.

### 1. تفاصيل النسخة الاحتياطية
- **الأداة المستخدمة**: `pg_dump (PostgreSQL) 16.3`
- **اسم قاعدة البيانات**: `nama_medical_web`
- **ملف النسخة الاحتياطية**: `namaweb/backups/catalog_override_pre_migration_backup.bak`
- **صيغة الحفظ**: مخصص مضغوط (`-F c`)
- **حالة العملية**: نجحت بنجاح كامل 100%.

### 2. التحقق من سلامة النسخ الاحتياطي
- تم فحص وتأكيد إنشاء الملف وحجمه في المجلد المحدد.
- تم فحص هيكلية الجداول والبيانات المسحوبة وتأكيد شموليتها لكافة جداول النظام البالغة أكثر من 120 جدولاً عملياتياً وعيادياً بما فيها جداول المرضى والمواعيد والكتالوجات الأساسية.

### 3. خطة الاستعادة في الطوارئ (Rollback & Recovery Plan)
في حال حدوث أي خلل في تشغيل التطبيق أو تلف البيانات:
1. يتم التراجع الهيكلي الفوري بتشغيل سكربت `catalog_override_down.sql` للتخلص من الجداول الجديدة وسياساتها.
2. إذا تطلب الأمر استرجاعاً كاملاً، يتم تنظيف قاعدة البيانات وإعادة استيراد ملف النسخ الاحتياطي بالكامل عبر الأمر:
   ```bash
   pg_restore -U postgres -d nama_medical_web -c backups/catalog_override_pre_migration_backup.bak
   ```
بذلك نضمن بقاء بيئة Staging في حالة تشغيلية مستقرة وآمنة في كافة الظروف.
