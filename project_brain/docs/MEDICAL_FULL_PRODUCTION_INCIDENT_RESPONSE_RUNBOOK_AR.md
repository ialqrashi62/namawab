# دليل الاستجابة للحوادث والتصعيد (Incident Response & Escalation Runbook)
## نظام نما الطبي (NamaMedical) - وثيقة التسليم النهائي

يوثق هذا الدليل الخطوات الفورية المعتمدة للاستجابة للمشاكل التشغيلية الطارئة والأعطال وحالات انقطاع الخدمة في بيئة الإنتاج الفعلي.

---

## 1. سيناريوهات الأعطال وحلولها السريعة (Common Incidents)

### الحالة الأولى: توقف التطبيق أو ظهور خطأ 502 Bad Gateway
1. **التحقق من الخدمة الخلفية**: تأكد من حالة تشغيل PM2:
   ```bash
   pm2 status
   ```
2. **إذا كانت الحالة معطلة أو تظهر إعادة تشغيل مستمرة**:
   افحص السجلات الفورية للمخرجات لمعرفة سبب الانهيار:
   ```bash
   pm2 logs nama-medical-erp --lines 100 --nostream
   ```
3. **إذا كان السبب تعذر ربط المنفذ**: تحقق من خلو المنفذ 3000 أو أعد تشغيل العملية بالكامل:
   ```bash
   pm2 restart nama-medical-erp
   ```

### الحالة الثانية: تعذر الاتصال بـ Redis أو ظهور خطأ الجلسات
1. **تحقق من حالة الخدمة**:
   ```bash
   systemctl status redis-server
   ```
2. **إذا كانت معطلة**:
   ```bash
   systemctl start redis-server
   ```
3. **إعادة تشغيل التطبيق** لربط الاتصال الجديد بـ Redis:
   ```bash
   pm2 restart nama-medical-erp --update-env
   ```

### الحالة الثالثة: توقف قاعدة البيانات أو ظهور أخطاء الاتصال
1. **تحقق من حالة PostgreSQL**:
   ```bash
   systemctl status postgresql
   ```
2. **إذا كانت معطلة**:
   ```bash
   systemctl start postgresql
   ```
3. **تحقق من حالة مساحة القرص**:
   ```bash
   df -h
   ```

---

## 2. آلية جمع سجلات التحقيق (Diagnostic Data Collection)

عند حدوث مشكلة حرجة ورغبة فريق الدعم في التحقيق:
* **حفظ سجلات Express و PM2**:
  ```bash
  pm2 logs nama-medical-erp --lines 300 --nostream > /tmp/app_crash_diagnostic.log
  ```
* **حفظ سجلات Nginx**:
  ```bash
  tail -n 200 /var/log/nginx/error.log > /tmp/nginx_error_diagnostic.log
  ```
* **حفظ سجلات النظام لـ Postgres**:
  ```bash
  tail -n 200 /var/log/postgresql/postgresql-12-main.log > /tmp/postgres_diagnostic.log
  ```

---

## 3. مسار وسلسلة التصعيد (Escalation Path)

في حال استمرار العطل بعد محاولة تطبيق كتاب التشغيل والحلول الأولية:
1. **المستوى الأول**: مشرف تشغيل السيرفرات (لإجراء الفحص المبدئي للشبكة ومساحة القرص).
2. **المستوى الثاني**: مهندس قاعدة البيانات (في حال وجود أخطاء RLS أو قفل جداول أو فقدان صلاحيات).
3. **المستوى الثالث**: فريق التطوير البرمجي (في حال وجود أخطاء برمجية في الكود المصدري أو ثغرات أمنية غير مغطاة).
4. **المستوى الرابع**: الإدارة الفنية لنظام نما الاستثماري (لاتخاذ قرارات الاستعادة الكلية أو إعلان وضع الطوارئ).
