# تقرير التحقق النهائي من الاستعادة والتراجع للإنتاج (Backup & Rollback Final Check Report)
## نظام نما الطبي (NamaMedical) - مرحلة التخطيط والتحقق

يوثق هذا التقرير الفحوصات الفنية النهائية لضمان سلامة النسخ الاحتياطي ووضوح مسارات التراجع والتعافي السريع (Rollback) في بيئة الإنتاج الفعلي للتخفيف من أي تأثير تشغيلي.

---

### 1. ضوابط التحقق من النسخ الاحتياطي (Backup Readiness)

* **الأداة المعتمدة للنسخ**: `pg_dump` بصيغة Custom Format (`-F c`) لتمكين الاسترداد المتوازي والسريع.
* **التحقق من المحتوى**:
  * يجب أن تشمل النسخة الهيكل الكامل لـ **148 جدولاً** بالإضافة لسياسات الـ RLS وبيانات التهيئة الأساسية.
  * يمنع تخزين أو تتبع النسخ في Git بشكل قاطع.
* **أهداف وقت واستعادة البيانات (RTO & RPO)**:
  * **RPO (نقطة استعادة البيانات)**: 0 دقيقة (لم يتم إجراء أي معاملات جديدة خلال النشر، حيث سيتم إيقاف التسجيلات الجديدة مؤقتاً).
  * **RTO (زمن التعافي المستهدف)**: أقل من 5 دقائق لإعادة تفعيل قاعدة البيانات بالكامل عند حدوث فشل حرج.

---

### 2. سيناريوهات ومحفزات التراجع الفوري (Rollback Triggers)

يتم إلغاء الترقية فوراً والتراجع للوضع المستقر السابق عند حدوث أي من السيناريوهات التالية خلال الـ 15 دقيقة الأولى من النشر:
1. ظهور تحذير تراجع متجر الجلسات إلى الميموري ستور (`MemoryStore fallback`) في سجلات خادم الويب.
2. فشل اتصال قاعدة البيانات أو فشل إنفاذ RLS بنسبة 100%.
3. عجز الطاقم الطبي عن تسجيل الدخول بنجاح برمز `200` أو ظهور أخطاء `500` متكررة في واجهة الصحة.
4. رصد أي تسريب أو تداخل في البيانات الطبية بين المستشفيات (مخالفة RLS).

---

### 3. خطوات تنفيذ التراجع (Rollback Execution Steps)

* **تراجع قاعدة البيانات والـ RLS**:
  في حال رصد أي مشكلة أمنية في الـ RLS، يتم إلغاء القسرية فوراً دون المساس بالبيانات:
  ```bash
  psql -h localhost -p 5432 -U postgres -d nama_medical_web -f docs/sql/production_readiness_force_rls_down.sql
  ```
  *(في حال حدوث تشوه أو فشل غير قابل للحل، يتم استعادة قاعدة البيانات فوراً من اللقطة السابقة عبر `pg_restore`).*

  رابط سكربت التراجع الهيكلي: [production_readiness_force_rls_down.sql](docs/sql/production_readiness_force_rls_down.sql)

* **تراجع كود التطبيق**:
  الولوج لخادم التطبيق والتراجع لالتزام النسخة المستقرة الأخيرة:
  ```bash
  # العودة للالتزام المستقر السابق (النسخة ما قبل النشر)
  git checkout <previous_stable_commit_hash>
  npm install --production
  pm2 restart nama-web
  ```

---

### 4. الخلاصة وحالة العبور (Gate Conclusion)

* **حالة بوابة التراجع والاستعادة**: **PASS** (تم توثيق وضمان مسارات التعافي الكامل وتأكيدها).
* **التوصية**: الانتقال للمستند الأخير لإعداد سجل مخاطر النشر.

**القرار**: تم تأكيد سلامة خطط الاستعادة والتراجع بنجاح (**Rollback Ready: PASS**).
