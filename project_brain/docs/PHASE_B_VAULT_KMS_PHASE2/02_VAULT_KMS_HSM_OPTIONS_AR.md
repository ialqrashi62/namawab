# Phase 2 — خيارات Vault / KMS / HSM (مقارنة)

> تحليل ورقي. لا إنشاء مفاتيح/شهادات. المعايير: قوة الأمان · ملاءمة on-prem · ملاءمة تنظيمية سعودية · حضانة المفتاح الخاص · mTLS · CSID/ZATCA · شهادات NPHIES · التعقيد التشغيلي · أثر النسخ/الاستعادة · التدوير · التدقيق · أنماط الفشل · التكلفة/التبعية.

## HashiCorp Vault (on-prem)
قوة عالية جداً · on-prem ممتاز · تنظيمي ممتاز (يبقى داخل المملكة/الموقع) · حضانة مفتاح خاص: transit/PKI engines · mTLS: نعم (PKI) · CSID/ZATCA: تخزين+توقيع عبر transit · NPHIES: حضانة شهادة/توقيع · تعقيد: عالٍ (unseal/HA/نسخ) · النسخ: مفاتيح معزولة، يجب تأمين Vault · تدوير: غني · تدقيق: ممتاز (audit devices) · فشل: تعطّل/unseal مفقود · تكلفة: تشغيل ذاتي (OSS) أو Enterprise.

## Azure Key Vault
قوة عالية (HSM-backed) · on-prem: متوسط (سحابة) · تنظيمي: يعتمد إقامة البيانات (منطقة) · حضانة: مفاتيح/أسرار/شهادات مُدارة · mTLS: شهادات مُدارة · CSID/ZATCA: تخزين مفتاح + توقيع · NPHIES: شهادات · تعقيد: متوسط · النسخ: مستقل عن البيانات (ممتاز) · تدوير: مدمج · تدقيق: ممتاز · فشل: تبعية شبكة/سحابة · تكلفة: سحابية + اتصال.

## AWS KMS + Secrets Manager
قوة عالية (HSM) · on-prem: متوسط · تنظيمي: حسب المنطقة/إقامة البيانات · حضانة: KMS لا يُصدِّر المفتاح؛ توقيع عبر KMS Sign · mTLS: ACM/Secrets · CSID/ZATCA: KMS asymmetric sign · NPHIES: ACM/Secrets · تعقيد: متوسط · النسخ: ممتاز · تدوير: مدمج · تدقيق: CloudTrail · فشل: تبعية شبكة/حساب · تكلفة: سحابية.

## GCP KMS + Secret Manager
مماثل لـAWS (HSM، asymmetric sign، تدقيق Cloud Audit Logs) · on-prem متوسط · تبعية سحابة · تكلفة سحابية.

## On-prem HSM (PKCS#11)
قوة عالية جداً (الأقوى لحضانة المفتاح الخاص) · on-prem ممتاز · تنظيمي ممتاز · حضانة/توقيع داخل العتاد (المفتاح لا يغادر) · mTLS/CSID/NPHIES: ممتاز · تعقيد: عالٍ + عتاد · النسخ: ممتاز (مفاتيح في العتاد) · تدوير: حسب الجهاز · تدقيق: جيد · فشل: عطل عتاد/HA · تكلفة: عتاد + خبرة.

## Windows Certificate Store / DPAPI bridge
قوة متوسطة · on-prem جيد لصندوق Windows · تنظيمي: محدود للإنتاج التنظيمي · حضانة: cert store (مفتاح خاص قابل للحماية بـDPAPI) · mTLS: ممكن لكن مربوط بالجهاز · CSID/NPHIES إنتاجي: **غير مُوصى** (machine-bound، DR هشّ) · تعقيد: منخفض · تدوير: يدوي · تدقيق: محدود · فشل: فقدان الجهاز/الملف · تكلفة: لا.

## Hybrid: DPAPI الآن → Vault/KMS لاحقاً (re-wrap)
قوة: قابلة للترقية · on-prem ممتاز · تنظيمي: يصبح ممتازاً عند الترقية · حضانة: DPAPI الآن ثم Vault/HSM للتنظيمي · تعقيد: منخفض→ · النسخ: محكوم (re-wrap الـDEK) · تدوير: عبر المزوّد · تدقيق: يتحسّن بالترقية · فشل: حسب المزوّد الحالي · تكلفة: تدريجية.

## ملخّص الترشيح
| الخيار | للأمان at-rest العام | للمفاتيح الخاصة التنظيمية (ZATCA/NPHIES) | on-prem |
|---|---|---|---|
| **Vault (on-prem)** | ممتاز | ممتاز (PKI/transit) | ✅✅ |
| **HSM on-prem** | ممتاز | الأقوى | ✅✅ |
| KMS سحابي (Azure/AWS/GCP) | ممتاز | ممتاز (إن قُبِلت السحابة + إقامة البيانات) | ⚠️ تبعية سحابة |
| DPAPI bridge | متوسط | غير مُوصى للإنتاج | ✅ |
| **Hybrid (DPAPI→Vault/HSM)** | قابل للترقية | عبر Vault/HSM لاحقاً | ✅✅ |
