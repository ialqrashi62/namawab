# تقرير جاهزية الرجوع - الدفعة الثالثة (Batch 3 Rollback Readiness Report)
## نظام نما الطبي (NamaMedical) - بيئة Staging

يوثق هذا التقرير الخطط والسكربتات والإجراءات الفورية اللازمة للتراجع عن التغييرات البرمجية أو الهيكلية في حال حدوث أي خلل أمني أو تشغيلي في مسارات الدفعة الثالثة.

---

### 1. إجراءات التراجع البرمجي (Code Rollback Procedures)
في حال استدعت الحاجة التراجع عن التعديلات المطبقة في الخادم `server.js`:
* **الأمر الفوري**:
  ```bash
  git restore server.js
  ```
  أو التراجع عن كامل الفرع التطويري عبر:
  ```bash
  git checkout -- .
  ```
* **التحقق من التراجع البرمجي**: إعادة تشغيل الخادم والتحقق من عودة الواجهات لحالتها السابقة المستقرة.

---

### 2. إجراءات استرداد واستعادة قاعدة البيانات (Database Restore Procedures)
نظراً لأننا لم نقم بتعديل الهيكل (No DDL applied) واقتصر العمل على النسخ بالقراءة فقط، فإن عملية استعادة البيانات المضمونة تتم عبر النسخة الاحتياطية المأخوذة بصيغة JSON:
* **مسار ملف الاستعادة**: `namaweb/backups/beds_batch3_data_backup.json`
* **آلية الاستعادة**:
  * كتابة سكربت Node.js بسيط يقرأ ملف الـ JSON ويقوم بإجراء عمليات تحديث/إدراج للصفوف الأصلية بعد تنظيف السجلات المدخلة للتجربة.
  * الفحص المباشر لقاعدة البيانات لضمان مطابقة أعداد السجلات وحالات الأسرة ليصبح مطابقاً لحالة ما قبل البدء.

---

### 3. سيناريو اختبار التراجع (Rollback Drill Scenario)
1. في حال تسبب التحديث في حظر جزئي لـ API:
   * يتم استعادة `server.js` من آخر التزام آمن (Commit).
   * يتم إعادة تشغيل اختبارات الانحدار `cross_tenant_inpatient_beds_test.js` للتأكد من استقرارية النظام الأساسي.
2. تم التحقق من سلامة وصلاحية ملف النسخ الاحتياطي `beds_batch3_data_backup.json` وتأكيد خلوه من أي تشوهات هيكلية أو نقص في البيانات.
