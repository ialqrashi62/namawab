# MEDICAL_POST_IMPLEMENTATION_MONITORING_AUTOPILOT_SKILL_AR

## الهدف
توفير إرشادات وقواعد موحدة لمرحلة مراقبة ما بعد التنفيذ (Post-Implementation Monitoring) على بيئة Staging لضمان استقرار نظام RLS والتحقق من عدم تراجع الحماية أو تسرب الأسرار.

---

## القواعد الأساسية للمراقبة (Monitoring Rules)

1. **حظر التعديل (Read-Only Validation)**:
   - يمنع تماماً تنفيذ أي DDL أو تعديل في مخطط الجداول (ALTER TABLE, CREATE TABLE).
   - لا يتم تشغيل `db push` أو `migrations` لحماية استقرار المخطط الحالي.

2. **فحص ونظافة سجلات التشغيل (Log Observation Guidelines)**:
   - عند فحص السجلات والـ Logs، يحظر تماماً طباعة أو حفظ أي اعتمادات تشغيل مثل `DATABASE_URL` أو `PGPASSWORD` أو الكوكيز وهاشات كلمات المرور.
   - التركيز على البحث عن استثناءات الـ RLS وحالات الفشل 500 ومطابقة المستأجرين.

3. **تدقيق الروابط ومصادر المستودع (Link and Repository Audit)**:
   - التأكد من خلو كافة التقارير الطبية والأمنية المضافة من أي مسارات مطلقة للمطور المحلي (`file:///` أو `C:\Users`).
   - استبدالها بروابط نسبية صحيحة للملفات داخل مستودع Git.

4. **تشغيل اختبارات انحدار الأمان (Security Regression Tests)**:
   - إعادة تشغيل اختبارات عزل الكتالوج، وحركات التنويم والأسرة، والخروج والإشغال بعد كل عملية تنظيف للتأكد من خلو النظام من أي ثغرات تراجع.

5. **تقييم الفجوة التشغيلية للإنتاج (Production Gap Assessment)**:
   - الحفاظ التام على تصنيف `PRODUCTION_READY: NO` حتى إتمام عزل موديولات الطوارئ، التمريض، والعمليات وتثبيت خطة نقل البيانات للإنتاج.
