## Tier-0 — Tenant-Isolated Tables (339)

All tables in this tier have:

- `ENABLE ROW LEVEL SECURITY`
- `FORCE ROW LEVEL SECURITY` (so even table owner is constrained)

- **SaaS-level** (one canonical instance across all tenants)

### Why these are NOT RLS-scoped

1. **Identity/RBAC layer (`system_users`, `user_mfa`, `permissions`)** — must be readable globally so a tenant-bound user can be authenticated before their tenant context is resolved. Tenant linkage happens via `user_tenants` table.

2. **Reference data (`icd10_codes`, `medications`, `lab_tests_catalog`, `radiology_catalog`)** — single canonical copy shared by all tenants. Updates propagate via `super_admin` tooling.

3. **SaaS infrastructure (`plans`, `plan_entitlements`, `saas_billing_*`, `finance_fiscal_years`)** — billing and entitlement infrastructure that exists above the tenant boundary.

4. **Migration tracking (`schema_migrations`)** — by definition must be readable by the bootstrap role before tenant context is known.

5. **PCC tokens (`pcc_api_tokens`)** — global to the PCC sandbox deployment. The PCC role (`nama_pcc_app`) is itself tenant-0, so all rows belong to the system context.

### Access enforcement (compensating controls)

Even though these tables have no RLS, access is still controlled by:

| Table | Compensation |
|---|---|
| `system_users` | App-level `requireAuth` + role-based `requireRole` middleware on all routes |
| `user_mfa` | `requireAuth` + `user.id === target` check; admin-reset requires `requireTenantAdmin` |
| `permissions` | Read-only via app routes; write only via `requireSuperAdmin` |
| `tenants` | Mutations only via `mountOnboardingRoutes` (super-admin gated) |
| `plans`, `plan_entitlements` | Admin-only routes (`requireRole('Admin')`) |
| `saas_billing_*` | `requireSuperAdmin` only |
| `schema_migrations` | DB superuser (postgres) only |
| `pcc_api_tokens` | PCC app token cache; no direct app route access |
| `icd10_codes`, `medications`, etc. | Read-only via `mountReferenceRoutes` (no write endpoints exposed) |

## What We Verified Live (2026-08-05)

```sql
-- Tier-0 (RLS + FORCE)
SELECT count(*) FROM pg_tables
WHERE schemaname='public' AND rowsecurity = true;
-- Result: 339

-- Tables with tenant_id but no RLS (REAL GAP — should be 0)
SELECT c.relname FROM pg_class c
JOIN pg_attribute a ON a.attrelid=c.oid
WHERE c.relkind='r' AND c.relnamespace=(SELECT oid FROM pg_namespace WHERE nspname='public')
  AND NOT c.relrowsecurity AND a.attname='tenant_id';
-- Result: 0 rows ✅

-- Tables with policy but no RLS (potential ORPHAN — should be 0)
SELECT count(*) FROM pg_policies WHERE schemaname='public' AND NOT EXISTS (
  SELECT 1 FROM pg_tables WHERE schemaname='public' AND tablename=pg_policies.tablename AND rowsecurity
);
-- Result: 0 ✅

-- Tier-1 count (no RLS, no tenant_id)
SELECT count(*) FROM pg_tables t
WHERE schemaname='public' AND NOT rowsecurity
  AND NOT EXISTS (SELECT 1 FROM information_schema.columns
    WHERE table_schema='public' AND table_name=t.tablename AND column_name='tenant_id');
-- Result: 30 (intentional global reference data)
```
