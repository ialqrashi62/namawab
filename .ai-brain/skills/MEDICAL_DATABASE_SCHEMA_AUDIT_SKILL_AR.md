# مهارة تدقيق مخطط قاعدة البيانات (Database Schema Audit)

## Purpose
تدقيق مخطط DB لجاهزية الطب/SaaS/المحاسبة: نماذج المرضى/الـ encounters/المواعيد/الكادر/الأقسام/أنواع المنشآت/المستأجرين/الأدوار/الصيدلية/المختبر/الأشعة/الفواتير/التأمين/المخزون/المشتريات/المحاسبة/التدقيق/الاستحقاقات.

## When to Use
عند تدقيق المخطط أو قبل أي DDL أو فحص تغطية tenant_id/RLS.

## Inputs Needed
db_postgres.js (CREATE TABLE + ALTER + RLS + الفهارس)، ملفات `docs/sql/*`.

## Procedure
فحوص خاصة:
1. هل كل جدول مملوك لمستأجر يحمل `tenant_id`؟ (قارن `CREATE TABLE` بـ `ALTER ... ADD tenant_id`).
2. هل MTN/MRN وأرقام الفواتير فريدة لكل tenant/منشأة؟
3. هل السجلات السريرية غير قابلة للتعديل حيث يلزم؟ سجلات التدقيق كاملة؟
4. حقول الدُفعة/الانتهاء بالصيدلية؟ تتبّع حركات المخزون؟ ربط موافقات التأمين بالفواتير؟
5. الفهارس على `tenant_id`، المفاتيح الأجنبية، حقول المال (decimal)، soft-delete، جداول مكرّرة/غير مستخدمة، مخاطر الترحيل.
6. **حوكمة RLS**: هل سياسات FORCE RLS متتبعة في المصدر أم على الإنتاج فقط؟ (تباين موثّق).

## Safety Rules
قراءة فقط. لا DDL. مقارنة المصدر بالإنتاج قراءة-فقط فقط، دون طباعة أسرار.

## Output Format
`docs/MEDICAL_DATABASE_SCHEMA_AUDIT_AR.md` — جداول مصنّفة + فجوات tenant_id/RLS/الفهارس + مخاطر.

## Done Criteria
كل الجداول الحساسة مُقيّمة لتغطية tenant_id/RLS/الفهارس، الفجوات والمخاطر موثّقة بأدلة.
