# مهارة تدقيق الأداء (Performance Audit)

## Purpose
تدقيق أداء النظام: الصفحات/الـ APIs البطيئة، تكلفة استعلامات لوحات التحكم، بحث المرضى، تقويم المواعيد، الترقيم، استعلامات N+1، الفهارس الناقصة، أنماط الاستعلام، حجم الحزمة، المكوّنات الثقيلة، فجوات التخزين المؤقت، توليد التقارير، نمو السجلات، صحة PM2، تجميع اتصالات DB، إنذارات rate-limit الكاذبة.

## When to Use
عند تدقيق الأداء أو قبل توسّع الأحمال أو عند شكاوى البطء.

## Inputs Needed
server.js (الاستعلامات، pool، rate-limit)، db_postgres.js (الفهارس)، public/js/app.js (حجم/مكوّنات)، سجلات PM2 (قراءة).

## Procedure
1. حدّد الاستعلامات الثقيلة/التجميعية (dashboards/reports) والفهارس الناقصة على `tenant_id`/الأعمدة المفلترة.
2. افحص الترقيم/التحميل الكسول للجداول الكبيرة، وN+1.
3. افحص `pg.Pool` (max)، rate-limit، وحجم app.js (10K سطر) وغياب bundling.
4. ملاحظة: الـ wrapper الجديد لـ pool.query (checkout لكل استعلام عند وجود tenant) له تكلفة — قيّمها.

## Safety Rules
قراءة فقط. لا اختبار حمل على الإنتاج بلا موافقة. لا طباعة أسرار من السجلات.

## Output Format
`docs/MEDICAL_PERFORMANCE_AUDIT_AR.md` — لكل مشكلة: الدليل | الأثر | الحل المطلوب | الاختبار المطلوب.

## Done Criteria
مشاكل الأداء الرئيسية مُحدّدة بأدلة وحلول وأولويات.
