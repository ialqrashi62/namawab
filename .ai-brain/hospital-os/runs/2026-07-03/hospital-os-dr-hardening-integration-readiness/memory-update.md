# تحديث الذاكرة للمشروع (Project Memory Update)

* **الوضع الجديد**:
  - تم إغلاق فجوات الاستعداد للكوارث بالكامل تشغيلياً وتوثيقياً.
  - تم وضع القرار المعماري ومسارات التقييم المعياري للتكامل والتحول الرقمي الرقمي (Mirth, FHIR R4).
  - تم تصحيح واستكمال تشغيل كافة الهجرات المتراكمة بنجاح 100% وإصلاح واجهة لوحة التحكم بعد معالجة الأقواس الناقصة والتخزين المؤقت.
* **إرشادات التطوير المستقبلي**:
  - يُمنع إدراج أي مفاتيح مشفرة أو أسرار أو بيانات مرضى (PHI) في بيئة التطوير.
  - يجب تفعيل قنوات Mirth بشكل مستقل وحراسة مسارات REST مع تمرير `tenant_id` لضمان استمرارية العزل التام للمستأجرين.
  - **قاعدة قيود العلاقات**: لا توجد علاقة مفتاح أجنبي مباشرة لجدول عام يسمى `visits` في النظام، بل يُشار إلى عمود `visit_id` كحقل `INTEGER` عادي أو بالرجوع إلى جداول مخصصة مثل `emergency_visits` لتجنب تعطل الهجرات.
  - **قاعدة كسر الكاش (Cache Busting)**: عند إجراء تعديلات هيكلية على ملف الجافا سكريبت الرئيسي `app.js` المخدم للإنتاج، يجب دائماً تحديث رقم الإصدار الممرر كمعامل استعلام (Query Parameter) في ملف `public/index.html` لضمان سحب المتصفحات وأجهزة التوجيه للنسخة الجديدة السليمة وعدم استخدام نسخة Cloudflare المخبأة التالفة.
  - **قائمة الانتظار والفرز الطبي (Triage / ESI)**: يجب أن يلتزم جدول `waiting_queue` بقيد التحقق `chk_waiting_queue_status` للقيم المعتمدة (CheckedIn, Triage, WaitingForProvider, InConsultation, WaitingForResults, ReadyForDischarge, NoShow). وعند إدخال أي سجل جديد، يجب تمرير `tenant_id` كحقل إلزامي لضمان التوافق التام مع سياسة RLS (`rls_waiting_queue_tenant_isolation`) المرتبطة بمتغير `current_setting('app.tenant_id')`.
  - **النداء الصوتي الذكي**: تم ربط استدعاء نداء المريض بنظام نطق النصوص المتطور في المتصفحات `window.speechSynthesis` بنظام لغتين تلقائي (SA-ar أو US-en) بناءً على لغة الواجهة المفعلة.
