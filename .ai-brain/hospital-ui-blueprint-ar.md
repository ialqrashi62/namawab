## 1. المبادئ الحاكمة للتصميم

| # | المبدأ | التفسير العملي |
|---|--------|----------------|
| 1 | Vanilla JS أولاً | لا أطر عمل جديدة؛ كل مكوّن دالة `render*()` + مستمعو أحداث + `escapeHTML()` إلزامي لكل مخرج نصي (درس XSS Layer-2) |
| 2 | نمطان معياريان فقط | **المحطة الثلاثية** (`ds-*` / `ns-*`) للأقسام السريرية، و**List+Drawer** للأقسام الإدارية/التشغيلية — أي قسم جديد يلتزم بأحدهما |
| 3 | RTL هو الأصل | العربية الفصحى افتراضياً، الإنجليزية طبقة ثانية عبر قاموس ترجمة؛ استخدام خصائص منطقية (`border-inline-start`, `margin-inline-end`) حصراً |
| 4 | متغيرات CSS للثيمات | كل لون عبر `var(--accent)`, `var(--card-bg)`, `var(--text-dim)`, `var(--accent-glow)`, `var(--hover)` — ممنوع الألوان الصلبة إلا لدلالات السلامة (أحمر حرج/أصفر تحذير) |
| 5 | السلامة قبل الجمال | أقسام SafetyGate تُلزم بـ: شريط هوية مريض دائم، تأكيد مزدوج للإجراءات الحرجة، ألوان إنذار موحّدة، ممنوع الحفظ الصامت |
| 6 | متعدد المستأجرين بصمت | لا عنصر واجهة يعرض بيانات خارج المستأجر؛ الثقة في RLS (150 سياسة FORCE) والجلسة، والواجهة لا تمرر `x-tenant-id` يدوياً |
| 7 | فلتر نوع المنشأة | كل مدخل قائمة جانبية يحمل مصفوفة أنواع المنشآت المسموح لها (17 نوعاً) كما هو معمول به حالياً |
| 8 | الحالات الأربع إلزامية | Empty / Loading / Error / Permission-denied مكوّنات موحّدة تُستدعى بلا استثناء في كل شاشة |

## 2. أساسات نظام التصميم (Design Tokens)

### 2.1 متغيرات الألوان (موجودة فعلياً — تُعتمد كما هي)

| المتغير | الاستخدام | مثال (ثيم افتراضي) |
|---------|-----------|---------------------|
| `--accent` | اللون الرئيس للإجراءات والتحديد | `#006970` (تركوازي نمى) |
| `--accent-hover` | حالة التحويم | `#004f54` |
| `--accent-glow` | هالات التركيز والظلال الملوّنة | `rgba(0,105,112,0.1)` |
| `--card-bg` | خلفية البطاقات واللوحات | `#ffffff` |
| `--text-dim` | النص الثانوي والوصفي | `#42474d` |
| `--hover` | خلفية تحويم صفوف القوائم | `#f1f5f9` |

الثيمات المتعددة الموجودة (أخضر/بنفسجي/أحمر/كهرماني/أزرق...) تبقى اختيار مستخدم، **لكن ألوان الدلالة السريرية ثابتة عبر كل الثيمات**:

| الدلالة | اللون | الاستخدام |
|---------|-------|-----------|
| حرج / إنذار أحمر | `#dc2626` | NEWS2 ≥ 7، ESI-1، نتيجة حرجة، حساسية دوائية |
| تحذير | `#f59e0b` | NEWS2 5–6، ESI-2، مخزون منخفض، تأخر إجراء |
| مستقر / ناجح | `#16a34a` | إتمام، توقيع، نتيجة طبيعية |
| معلوماتي | `#2563eb` | حالات محايدة، إشعارات نظام |
| معلّق / مسودة | `#64748b` | حالات انتظار وموافقات |

### 2.2 الطباعة والأيقونات

| العنصر | المواصفة |
|--------|----------|
| الخط | الخط الحالي للنظام (system stack عربي)؛ أرقام حيوية بموازين كبيرة `font-weight:700` |
| مقاسات | عنوان لوحة 18–20px، عنوان بطاقة 14px، نص 13px، وصفي 11px (مطابق `.ns-worklist-meta`) |
| الأيقونات | مجموعة الأيقونات الحالية (emoji/SVG inline)؛ كل قسم أيقونة ثابتة تظهر في القائمة + رأس الصفحة + تبويب المتصفح |
| الاتجاه | أيقونات الأسهم تنعكس تلقائياً في RTL عبر `transform: scaleX(-1)` على فئة `.dir-flip` |

## 3. النمط المعياري الأول: المحطة الثلاثية السريرية (`ds-*` / `ns-*`)

هذا هو النمط الإلزامي لكل الأقسام السريرية الجديدة (تخدير، PACU، NICU، OPD، محطات التمريض التخصصية...).

### 3.1 البنية (مطابقة للكود الفعلي)

```
+---------------------------------------------------------------+
| شريط هوية المريض الدائم (اسم/رقم ملف/عمر/جنس/حساسيات/أعلام)   |
+----------------+---------------------------+------------------+
| Worklist يمين  |   المحتوى الأوسط          |  الإجراءات يسار  |
| (RTL: يمين)    |   (تبويبات القسم)         |  (RTL: يسار)     |
| قائمة مرضى     |   توثيق/نتائج/أوامر       |  أوامر سريعة     |
| بحث + فلاتر    |   مخططات/جداول           |  ملخص/تنبيهات   |
+----------------+---------------------------+------------------+
```

- Grid: `grid-template-columns: 280px 1fr 300px` → عند `1280px`: `240px 1fr 260px` → عند الجوال: عمود واحد `auto 1fr auto` (كما في `.ds-layout` / `.ns-layout` الحاليتين).
- في RTL يكون العمود الأول (worklist) على اليمين تلقائياً لأن الشبكة تتبع اتجاه المستند.

### 3.2 مكوّنات المحطة القياسية

| المكوّن | الفئة | المواصفة |
|---------|-------|----------|
| عنصر قائمة العمل | `.ns-worklist-item` | Avatar دائري بالحروف + اسم `font-weight:700` مع ellipsis + سطر meta 11px + شارة حالة ملوّنة؛ النشط: `border-inline-start: 3px solid` بلون القسم |
| رأس اللوحة | `.ds-panel-header` | عنوان + عدّاد + زر تحديث + فلتر سريع |
| شريط هوية المريض | `.pt-banner` (جديد موحّد) | ثابت أعلى العمود الأوسط؛ يعرض: الاسم، MRN، العمر/الجنس، فصيلة الدم، أعلام (حساسية 🔴 / عدوى 🟡 / سقوط 🟠 / DNR ⚫)، NEWS2 الأخير |
| تبويبات المحتوى | `.ds-tabs` | أفقية قابلة للتمرير `overflow-x:auto`؛ التبويب النشط بخط سفلي `--accent` |
| عمود الإجراءات | `.ds-actions` | بطاقات إجراء رأسية: أوامر سريعة، تنبيهات حرجة، ملخص اليوم، أزرار توقيع/اعتماد |

### 3.3 الحالات القياسية داخل المحطة

| الحالة | السلوك |
|--------|--------|
| Empty (لا مريض محدد) | رسم توضيحي خفيف + «اختر مريضاً من قائمة العمل» + اختصار بحث |
| Loading | Skeleton صفوف رمادية نابضة في العمود المحمّل فقط (لا تجميد كامل) |
| Error | بطاقة حمراء داخل العمود المتأثر + زر «إعادة المحاولة» + رمز الخطأ للدعم |
| Permission-denied | استبدال المحتوى بقفل 🔒 + «لا تملك صلاحية هذا القسم» + زر طلب صلاحية (يرسل للمدير) |

## 4. النمط المعياري الثاني: List + Drawer (الأقسام الإدارية/التشغيلية)

للأقسام: المالية، المخازن، الموارد البشرية، الجودة، الصيانة، العقود، اللجان، سجل التدقيق...

### 4.1 البنية

```
+---------------------------------------------------------------+
| رأس الصفحة: عنوان + أزرار (إنشاء / تصدير / طباعة / فلاتر)     |
+---------------------------------------------------------------+
| صف بطاقات KPI (3–5 بطاقات إحصائية قابلة للنقر = فلتر)          |
+---------------------------------------------------------------+
| شريط أدوات: بحث + فلاتر منسدلة + محدد نطاق تاريخ + عرض/كثافة  |
+---------------------------------------------------------------+
| جدول رئيسي (فرز بالأعمدة، ترقيم صفحات، تحديد متعدد)  | Drawer |
|                                                        | جانبي |
+---------------------------------------------------------------+
```

- **Drawer** ينزلق من الجهة المقابلة للقراءة (يسار في RTL) بعرض `480px` (جوال: ملء الشاشة)، يعرض التفاصيل/النموذج دون مغادرة القائمة.
- التحديد المتعدد يُظهر شريط إجراءات جماعية عائماً أسفل الجدول (اعتماد جماعي، تصدير المحدد...).

### 4.2 مواصفة الجدول القياسي

| الخاصية | المواصفة |
|---------|----------|
| الفرز | نقرة على رأس العمود؛ سهم اتجاه؛ فرز خادمي للجداول الكبيرة |
| الترقيم | 25/50/100 صفاً + عدّاد إجمالي |
| الأعمدة | أول عمود = المعرّف/الاسم (ثابت)، آخر عمود = إجراءات (⋮ قائمة) |
| الحالة | شارات ملوّنة موحّدة (§2.1) |
| التمرير | الجدول داخل حاوية `overflow-x:auto` — الصفحة لا تتمرر أفقياً أبداً |

## 5. مكتبة المكوّنات المشتركة (تُبنى مرة وتُستدعى في كل قسم)

### 5.1 مدخل القائمة الجانبية (Sidebar Entry)

القائمة الحالية 44 مدخلاً مسطّحاً بفهرس رقمي؛ **المخطط الجديد**: مجموعات A–J قابلة للطي مع الحفاظ على الفهرس الرقمي للتوافق الخلفي.

| الخاصية | المواصفة |
|---------|----------|
| البنية | رأس مجموعة (A–J) قابل للطي + مداخل فرعية؛ حالة الطي محفوظة في `localStorage` |
| المدخل | أيقونة + تسمية عربية (EN عند تبديل اللغة) + شارة عدّاد اختيارية (مهام معلّقة) |
| الصلاحية | المدخل يُخفى كلياً عند غياب الصلاحية (لا تعطيل رمادي) — مطابق للسلوك الحالي |
| فلتر المنشأة | مصفوفة أنواع منشآت لكل مدخل (17 نوعاً) — عيادة أسنان لا ترى بنك الدم |
| بحث القائمة | حقل بحث أعلى القائمة يفلتر المداخل فورياً (لـ 75+ قسماً مستقبلاً) |

### 5.2 بطاقات لوحة القسم (Dashboard Cards)

| النوع | المحتوى | التفاعل |
|-------|---------|---------|
| بطاقة عدّاد | رقم كبير + عنوان + دلتا (▲▼ عن أمس) | نقرة = فلترة القائمة |
| بطاقة إنذار | عدّاد أحمر نابض للحالات الحرجة (نتائج حرجة، NEWS2≥7) | نقرة = قائمة الحالات الحرجة |
| بطاقة قائمة مصغّرة | أحدث 5 عناصر (أحدث تنويم، آخر بلاغ) | «عرض الكل» |
| بطاقة مخطط | شريطي/خطي مصغّر (7 أيام) عبر SVG يدوي خفيف | تلميح عند التحويم |

### 5.3 درج الاعتماد (Approval Drawer) — مكوّن موحّد جديد

| العنصر | المواصفة |
|--------|----------|
| الاستدعاء | أي كيان بحالة «بانتظار اعتماد» يعرض زر «اعتماد/رفض» يفتح الدرج |
| المحتوى | ملخص الكيان + سلسلة الموافقات (من→إلى) + حقل سبب إلزامي عند الرفض |
| التوقيع | إعادة إدخال كلمة المرور أو PIN للاعتمادات الحرجة (دم، أدوية عالية الخطورة، قيود مالية) |
| Idempotency | زر الاعتماد يُعطَّل فور النقر + مفتاح idempotency (مطابق لنمط المال الحالي) |
| السجل | كل اعتماد/رفض يسجَّل تلقائياً في الخط الزمني للتدقيق |

### 5.4 الخط الزمني للتدقيق (Audit Timeline) — مكوّن موحّد جديد

| العنصر | المواصفة |
|--------|----------|
| الموقع | تبويب «السجل» في كل صفحة تفاصيل |
| العنصر الواحد | أيقونة نوع الحدث + من (اسم+دور) + ماذا (إنشاء/تعديل/اعتماد/طباعة/عرض PHI) + متى (نسبي+مطلق) |
| التعديلات | «عرض الفرق» يظهر قبل/بعد للحقول المتغيرة |
| القراءة فقط | لا حذف ولا تعديل من الواجهة إطلاقاً |
| المصدر | نفس بيانات سجل التدقيق المركزي (قسم J-عارض التدقيق يعرضها عبر كل الأقسام) |

### 5.5 المرفقات (Attachments)

| العنصر | المواصفة |
|--------|----------|
| الرفع | سحب-إفلات + زر؛ أنواع مسموحة معلنة؛ حد حجم ظاهر |
| التخزين | عبر مسار PHI المحمي (`/api/phi-files/:id` — نمط A3A: مصادقة + RLS + تدقيق) — **ممنوع** أي webroot عام |
| العرض | شبكة مصغّرات (صور/PDF) + معاينة داخل modal؛ تنزيل يسجَّل في التدقيق |
| الوسم | تصنيف المرفق (تقرير، موافقة موقعة، صورة سريرية) إلزامي |

### 5.6 الملاحظات (Notes)

| العنصر | المواصفة |
|--------|----------|
| الأنواع | ملاحظة حرة / قالب منظّم (SOAP للسريري، SBAR للتمريض — موجودان) |
| السلوك | إضافة فقط (append-only)؛ التعديل بعد التوقيع = ملحق تصحيحي (نمط `emr_amendments` الموجود) |
| التوقيع | «توقيع وقفل» يحوّل الملاحظة للقراءة فقط ويختمها بالاسم والوقت |
| الإشارة | @إشارة لمستخدم ترسل تنبيهاً عبر قسم الرسائل |

### 5.7 الطباعة والتصدير (Print/Export)

| القناة | المواصفة |
|--------|----------|
| طباعة | CSS `@media print`: إخفاء القائمة/الأزرار، ترويسة المنشأة (شعار المستأجر)، تذييل (طبع بواسطة/التاريخ/رقم الصفحة)، QR للتحقق للوثائق الرسمية |
| PDF | عبر نافذة الطباعة (بلا مكتبات خارجية) |
| Excel/CSV | تصدير القائمة الحالية بفلاترها؛ UTF-8 مع BOM لسلامة العربية في Excel |
| الضبط | كل طباعة/تصدير تسجَّل في التدقيق (من طبع ماذا ومتى) — متطلب PHI |

### 5.8 الحالات الأربع الموحّدة (مكوّن `renderState()`)

| الحالة | البصريات | النص العربي | النص الإنجليزي |
|--------|----------|-------------|----------------|
| Empty | أيقونة خفيفة + CTA | «لا توجد سجلات بعد — ابدأ بإنشاء أول سجل» | "No records yet — create your first one" |
| Loading | Skeleton نابض (لا spinner للجداول) | «جارٍ التحميل...» | "Loading..." |
| Error | بطاقة حمراء + رمز خطأ + إعادة محاولة | «تعذّر تحميل البيانات — أعد المحاولة» | "Failed to load — retry" |
| Permission-denied | قفل 🔒 + مسار التصعيد | «لا تملك صلاحية الوصول لهذا القسم» | "You don't have permission to access this section" |

### 5.9 الاستجابة (Responsive) — نقاط الكسر المعتمدة

| النطاق | المحطة الثلاثية | List+Drawer |
|--------|-----------------|-------------|
| ≥ 1440px | `280px 1fr 300px` | جدول كامل + Drawer 480px |
| 1280–1439 | `240px 1fr 260px` (موجود) | جدول كامل + Drawer 420px |
| 768–1279 | worklist ينهار لشريط أفقي علوي قابل للتمرير؛ الإجراءات تنتقل لأسفل | البطاقات 2×N؛ Drawer ملء الشاشة |
| < 768 | عمود واحد `auto 1fr auto` (موجود)؛ تنقّل بين الأعمدة بأزرار سفلية ثابتة | الجدول يتحول لبطاقات مكدّسة؛ الفلاتر في bottom-sheet |

### 5.10 RTL/LTR والتعريب

| القاعدة | المواصفة |
|---------|----------|
| الاتجاه | `dir="rtl"` على الجذر؛ التبديل للإنجليزية يقلب لـ`ltr` كاملاً |
| الخصائص | منطقية فقط: `inline-start/end`, `text-align:start` — ممنوع left/right صريح |
| الأرقام | أرقام غربية (0-9) دائماً للجرعات والمعرّفات الطبية (سلامة)؛ التاريخ ميلادي + هجري اختياري في الوثائق الرسمية |
| القاموس | ملف `i18n` واحد `{key: {ar, en}}`؛ كل تسمية في هذا المخطط لها المفتاحان |
| المختلط | أسماء الأدوية/الفحوصات تبقى لاتينية داخل النص العربي مع `dir="ltr"` مضمّن + `unicode-bidi: isolate` |

## 6. مخططات الأقسام — المجموعة A: وصول المرضى (Patient Access)

| القسم | التسمية EN | النمط | بطاقات اللوحة | القائمة | التفاصيل | نماذج/خصوصيات |
|-------|-----------|-------|----------------|---------|-----------|----------------|
| الاستقبال والتسجيل MPI (موجود) | Registration & MPI | List+Drawer | تسجيلات اليوم، مرضى جدد، تكرارات محتملة، متوسط زمن التسجيل | بحث MPI متقدم (اسم/هوية/جوال/MRN) + كشف التكرار | ملف ديموغرافي + وثائق + تأمين + أقارب | نموذج تسجيل بخطوات (هوية→تواصل→تأمين→موافقات)؛ دمج التكرارات بموافقة مشرف عبر درج الاعتماد |

## 18. ملاحظات تنفيذية ختامية (قيود لا تُخالف)

1. كل ما سبق **تخطيط واجهات فقط** — أي DDL (جداول اعتماد/تدقيق جديدة) يمر عبر بوابات المالك المعلّقة، لا يُنفَّذ من هذه الوثيقة.
2. الالتزام بـ`escapeHTML()` في كل مكوّن جديد (373 موقعاً محمياً حالياً — لا تراجع).
3. المرفقات حصراً عبر نمط `phi_vault` + `/api/phi-files/:id` — ممنوع أي ملف PHI في webroot.
4. الشاشات الجديدة لا تضيف مسارات تتجاوز RLS أو تقرأ عبر `x-tenant-id` — الجلسة هي مصدر الحقيقة (Gate 4).
5. أزرار المال والاعتماد الحرج تحمل مفاتيح idempotency (نمط Gate 7 الموجود).
6. أي شاشة عرض عامة (طوابير/kiosk) تعرض حداً أدنى من الهوية (الاسم الأول + رقم طابور) — لا PHI كامل.
